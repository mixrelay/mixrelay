# MixRelay 제품 명세

MixRelay는 출시 전 개발 중인 macOS·Linux 오디오 라우팅 제품이다.
기능·정책·구현 상태는 이 문서에서 관리한다. 작업 일지나 시험별 이력은 누적하지 않는다.
현재 검사 범위는 [검증 현황](validation/current.md), 공통 UI 규격은
[디자인 시스템](design-system.md)과 [조작·접근성 계약](design/interaction-accessibility.md)을 따른다.

## 제품 구성

무료·유료 기능은 같은 MixRelay 제품·설치본·버전을 사용한다. Driver는 내부 장치·오디오 구성요소다.
단일 제품의 설치·업데이트 기준은 아래 설치와 판매 절을 따른다.

기본 가상 장치의 사용과 편집 앱의 그래프 기능은 별도 범위다. 무료 가상 장치 1개는
지원 범위인 방향별 최대 64채널을 사용할 수 있고, 채널·샘플레이트·PCM 설정과 기본 루프백을 제공한다.
OS·외부 DAW에서 이 장치를 사용하는 채널 수에 편집 앱의 노드·매핑 한도를 적용하지 않는다.

### 편집 앱의 무료 기능 범위

| 기능 | 무료 범위 |
| --- | --- |
| 그래프 | 1개, 저장·불러오기·복원 가능 |
| 마이크·물리 장치 입력과 개별 앱 캡처 | 입력 노드 합계 2개 |
| 출력 장치 | 서로 다른 장치 합계 2개, 가상 장치 출력도 포함 |
| 편집 그래프에서 가상 장치로 보내는 채널 연결 | 합계 4개, 스테레오 연결 하나는 2개로 계산 |
| 내장 처리·효과 | 개수 제한 없음, 프리셋·파라미터 편집 포함 |
| 외부 플러그인 | 인스턴스 합계 2개 |
| 녹음 | 레코더 1개, 최대 2채널, 녹음당 누적 2시간 |
| 전체 시스템 오디오 캡처 | 유료 기능 |

유료는 위 그래프·입력·출력·매핑·외부 플러그인·레코더의 무료 한도를 해제하고,
전체 시스템 캡처, 가상 장치 추가·이름 변경을 제공한다. 플랫폼과 엔진의 기술적 상한은 유지한다.
장치·그래프·매핑의 저장과 복원은 무료 범위에서도 제공한다.

무료 앱은 기간 제한 없는 기능 제한 체험이다. 음질 저하·잡음·추가 지연을 넣지 않는다.
무료 장치는 이름을 바꿀 수 없지만 지원하는 채널·샘플레이트·PCM 설정은 사용할 수 있다.

- 입력 2개는 물리 장치 입력·개별 앱 캡처 노드 수다. 노드가 제공하는 채널 수를 세지 않는다.
  가상 장치에서 소리를 받아오는 노드와 처리·출력·레코더 노드는 이 입력 한도에 포함하지 않는다.
  전체 시스템 캡처는 개별 앱 입력 한 개로 취급하지 않고 유료 기능으로 판정한다.
- 출력 2개는 노드 수가 아니라 서로 다른 출력 장치 수다. 같은 장치를 여러 노드에서 선택해도 한 번만 센다.
  가상 장치로 보내는 출력도 장치 하나로 세며 레코더는 출력 장치 수에서 제외한다.
- 매핑 4개는 편집 그래프에서 가상 장치로 보내는 실제 채널 연결만 합산한다.
  내장 효과 사이·물리 출력·레코더로 이어지는 연결, 가상 장치에서 받아오는 채널,
  기본 Driver 루프백과 외부 DAW의 장치 사용에는 이 매핑 한도를 적용하지 않는다.
  가상 장치를 일반 오디오 장치로 선택해도 같은 장치 ID의 출력·매핑으로 센다.
- 외부 플러그인은 Off 상태를 포함한 인스턴스 수로 센다. 검색 목록 수는 제한하지 않는다.
  내장 효과·믹서·게인 등 내장 처리는 외부 플러그인 한도에 포함하지 않는다.
- 파일 불러오기·외부 제어에도 같은 엔진 한도를 적용한다.
- 무료 전환 시 기존 그래프·장치·녹음과 현재 작업을 보존한다. 초과 구성의 추가·새 실행에는 무료 한도를 적용한다.
  재시작 시 무료 범위의 장치·그래프 하나를 사용할 경로를 제공하며 초과 구성을 자동 삭제하지 않는다.

### 이용 허가와 제품 편입

무료 Driver는 독점 소프트웨어이며 무료 사용이 소스 공개·수정·재배포 허가를 뜻하지 않는다.
개인·기업의 방송·녹음·업무 도구 사용은 허용한다. OEM·번들·재판매·화이트라벨·상용 제품 편입은
사전 서면 허가와 별도 계약이 필요하며 일반 앱 구매에 포함되지 않는다.
제3자 구성요소의 원래 권리·고지는 유지한다.

약관 원문은 [앱](../LICENSE.txt)과 [Driver](../LICENSE-Driver.txt)로 구분한다.
사업자는 에코 비전 랩(Echo Vision Lab), 지원 연락처는 `support@mixrelay.com`이다.
계약서의 사업자 정보와 판매 채널의 법정 고지를 맞추며 설치 약관에 대표자 개인 이름을 넣지 않는다.
계약·개인정보·제3자 고지 기준은 [법무 검토](legal-review.md)를 따른다.

### 지원 언어

영어·일본어·한국어·중국어 간체/번체·프랑스어·독일어·스페인어·포르투갈어·이탈리아어·러시아어를 지원한다.
앱 UI·오류·접근성 문구, 실행부 메뉴·장치 설정, App·Driver 구성요소의 약관 전문, 설치·제거 안내에 함께 적용한다.
OS/브라우저 선호 목록의 첫 지원 언어를 사용하며 없으면 영어를 사용한다.
중국어는 Hans/Hant를 우선하고 TW·HK·MO는 번체, CN·SG·일반 zh는 간체로 해석한다.
제품명·기술 식별자·서버 진단 로그는 원래 표기를 유지한다.

약관의 내용은 언어별로 동일해야 하며 임의의 영어 우선 조항을 추가하지 않는다.
원문과 패키지 리소스 대응은 [언어 목록](../packaging/localization/languages.json)에 둔다.
새 기능·계약 변경은 전체 지원 언어에 함께 반영하고 긴 문구·CJK·좁은 창·접근성 이름을 확인한다.

## 실행 책임과 수명

| 계층 | 책임 |
| --- | --- |
| 편집 앱 | 그래프·장치 설정 편집, 파일 선택, 현재 실행 상태 표시 |
| Driver 일반 사용자 실행부 | 상태 메뉴, 인증 저장, 캡처·라우팅·DSP·플러그인·녹음과 유료 기능 경계 |
| HAL·native 장치 소유자 | 가상 장치 등록, 기본 루프백, 형식과 PCM 전송 |
| 공통 엔진·I/O | 실행 계획·블록 처리·제어 계약·클록과 자원 소유권 |
| OS 어댑터 | CoreAudio·PipeWire 협상과 플랫폼 ABI |
| 설치 패키지 | 앱·Driver 실행부의 설치·업데이트·제거 |

HAL과 오디오 콜백에서 네트워크 인증이나 저장소에 접근하지 않는다. 플랫폼 ABI 외의 정책·수명은 Rust가 소유한다.
macOS는 AudioServerPlugIn HAL과 XPC/shared memory, Linux는 PipeWire를 사용한다.
그래프 파일에 native handle을 저장하지 않는다. 공유 PCM은 단일 writer·명시적 수명·epoch를 유지한다.
부분 입력의 남은 영역은 지우고 입력 부족과 정상 무음을 구분한다. 뒤의 오류로 완료된 sink write를 되돌리지 않는다.
장치 제거는 새 I/O를 막고 콜백을 배출한 뒤 버퍼를 해제한다. 늦은 종료 호출용 정보는 마지막 참조까지 유지한다.

편집 앱을 종료해도 실행 중인 라우팅·캡처·DSP·플러그인·녹음은 유지한다.
다시 열면 같은 실행부의 현재 상태에 연결한다. macOS 창 닫기는 창을 숨기고 앱 종료는 편집 프로세스만 종료한다.
Linux 창 닫기는 편집 프로세스를 종료한다. 같은 MixRelay의 백그라운드 실행 모드는 별도 Dock 항목을 만들지 않는다.

macOS의 명시적 **백그라운드 실행 중지**는 편집 앱 종료와 구별한다.
편집 앱의 명시적 연결은 앱 번들의 작은 비 UI 런처를 직접 시작한다.
런처는 같은 MixRelay 실행 파일의 내부 백그라운드 모드를 자식으로 실행한다.
앱과 오디오 구성요소는 함께 업데이트하며, 런처는 Dock 중지 신호를 실행부에 전달하고 종료를 기다린다.
로그인 시 자동 실행·종료 후 자동 재시작은 사용하지 않는다. macOS의 백그라운드 활동 허용 설정을 존중한다.
시스템이 Driver 실행부에 보내는 AppKit 종료·SIGTERM은 Driver 종료와 같은 경로에서 처리한다.
새 명령과 대기 중 장치 활성화를 차단하고 HAL 장치·루프백을 중지·저장한 뒤
캡처·그래프·녹음을 마무리하고 실행부를 종료한다. 실행부가 강제로 사라지면
엔진의 소유권 감시도 녹음 마무리와 Driver 중지를 수행한다.
편집 앱의 일반 종료·창 닫기·상태 조회는 이 경로를 호출하지 않는다.

Driver의 명시적 종료는 장치·루프백을 중지하고 진행 중 명령을 배출하며 녹음을 마무리한다.
설정과 중지 상태를 보존하고 종료 실패 시 재시도할 수 있게 관리 UI를 유지한다.
서비스 재시작이나 상태 조회만으로 명시적으로 중지한 오디오를 재개하지 않는다.
실행부 시작은 명시적 연결 경로에서 수행하며 소유권 확보 전에 제어 소켓을 게시하지 않는다.
제어 서비스는 다음 시작 요청을 받을 수 있도록 남는다. 실행 중인 macOS HAL 루프백은 제어 서비스 재시작에도 유지한다.

전체 일시정지는 그래프·앱 캡처를 멈추고 설정을 유지한다. 재개할 때까지 엔진 재시작·앱 재실행·재부팅 뒤에도
일시정지를 유지한다. 진행 중 녹음은 같은 파일에서 재개하며 일시정지 구간을 무음으로 기록하지 않는다.
실행부가 오디오를 소유하는 동안 엔진이 비정상 종료되면 엔진을 다시 시작해 저장된 그래프·일시정지 상태를 복원하고
앱 캡처를 새 엔진에 다시 연결한다. 사용자가 중지·종료한 오디오는 다시 시작하지 않는다. 개별적으로 일시정지·정지·삭제한 녹음을 자동 시작하지 않는다.
일시정지 중에도 가상 장치와 그 ID·이름·형식을 유지한다.
사용자 동작 설명은 [매뉴얼](manual/playback.md)에 둔다.

## 가상 오디오 구성요소

Driver는 장치 구성마다 다시 설치하지 않는다. 기본 장치 이름은 `MixRelay IO`이며 안정적인 ID를 유지한다.
유료 앱에서 만든 장치도 편집 앱 종료 후 유지한다. 장치 추가·제거·이름 변경은 인증된 앱에서만 제공한다.
무료 장치 설정은 구매 인증 없이 상태 메뉴와 앱에서 바꿀 수 있다.

### 장치 설정

| 플랫폼 | 방향별 채널 | 가상 장치 형식 |
| --- | --- | --- |
| macOS arm64·x86_64 | 1–64 | 44.1/48/88.2/96/176.4/192 kHz, Float32·PCM16·packed PCM24·PCM32 |
| Linux arm64·x86_64 | 1–64 | PipeWire에서 지원하는 F32·PCM16·packed PCM24·PCM32 조합 |

물리 장치는 하드웨어의 지원 범위를 따른다. 내부 DSP는 Float32이며 녹음 파일 형식은 별도다.
장치 native 형식·OS client 변환·내부 DSP 형식을 구분한다. PCM24는 packed 3바이트다.

- 앱은 가상 장치 노드 Options에서 이름·공통 채널 수·샘플레이트·비트 심도를 편집한다.
  별도 전역 Driver 설정 모달을 두지 않는다.
- 독립 메뉴는 공통 샘플레이트·비트 심도·채널 수를 제공한다. 채널 메뉴는 지원하는 2·4·8·16·32·64로 제한한다.
  백엔드의 1–64채널 계약은 유지하며 기타·범위 메뉴를 추가하지 않는다.
- 채널·PCM은 양방향에서 실제로 함께 지원하는 조합만 적용한다. 값이 불일치하거나 미확인인 경우 임의 값을 표시하지 않는다.
- 장치 선택은 안정적인 ID, 기능 선택은 실제 capability를 사용한다.
  `nativeFormats`와 공통 제어 트랜잭션을 공유하고 앱에 OS별 설정 프로토콜을 만들지 않는다.
- 변경은 정지·배출·협상·readback·게시 순서로 처리한다. 실패 시 이전 형식·설정을 보존하고 복원 실패를 알린다.
  외부 DAW·OS의 변경을 오래된 요청으로 덮어쓰지 않는다.
- 장치의 nominal Hz와 실제 클록을 구분하고 독립 클록 경계에서 한 번만 보정한다.

상태 메뉴는 백그라운드 실행부의 상태 아이콘 하나에만 둔다. 상단은 `MixRelay {설치 버전}`이다. 첫 묶음은 장치·앱 열기·일시정지/재개,
두 번째 묶음은 업데이트 확인·결과·[진단 리포트 저장](#수동-진단-리포트)·종료이며 구분선은 하나다. 앱 열기는 편집 앱이 있을 때만 표시한다.
종료는 모든 오디오를 멈춘 뒤 끝나며, 실패하면 실행부와 종료 항목을 유지하고 지역화된 안내를 표시한다.
업데이트 결과는 메뉴 안에 표시하고 다운로드가 있으면 링크를 제공한다. 자동 설치·별도 결과 팝업은 사용하지 않는다.

### macOS 장치 Transport 호환성

HAL의 `kAudioDevicePropertyTransportType`은 기본적으로 `virt`다. 가상 장치를 숨기거나 거부하는 앱의 정확한 번들 ID에만 `usb `를 응답한다. Driver 서비스가 목록을 소유하며 기본값은 Loopback/ARK 현장 동작에서 확인된 `com.tencent.tencentmeeting`, `net.whatsapp.WhatsApp`, `com.motu.DigitalPerformer`, `com.vmware.fusion`, `com.goodnotesapp.x`다. 이는 표시 호환성으로, 권한·장치 UID·오디오 경로를 바꾸지 않는다.

v1 inventory의 `transport_compatibility` 배열은 필수다. 빈 배열은 빈 정책이고, 필드가 없거나 잘못된 목록·오래된 세대의 스냅샷은 거부해 마지막 유효 인벤토리와 정책을 보존한다. CoreAudio가 클라이언트 등록 때 알려 준 콜백 번들 ID를 복사해 그 PID의 마지막 클라이언트가 제거될 때까지 응답에 쓴다. 설치된 HAL은 샌드박스 때문에 다른 프로세스를 조회할 수 없으므로 등록된 번들은 조회가 실패해도 응답한다. 시작 시각 조회는 속성 읽기 기한 안에서 계속 시도하며, 읽을 수 있고 등록 때와 다르면 PID가 재사용된 것으로 보고 그 번들을 버린다. 등록된 번들이 없고 조회도 막히면 `virt`를 유지한다. 목록 변경 시 잠금을 해제한 뒤 `tran` 속성 변경을 알린다. 서비스 환경 변수 `MIXRELAY_TRANSPORT_COMPATIBILITY`로 HAL 재빌드 없이 개발 목록을 교체하거나 빈 값으로 끌 수 있다. [규격·설치본 확인 절차](../native/macos/hal-driver/README.md#transport-type-compatibility)를 따른다.

### 가상 장치의 버퍼 관리

장치별 버퍼 선택기는 두지 않는다. 엔진이 가상 장치에 연 I/O 버퍼는 물리 장치와 같이 오디오 설정의 버퍼 크기를 따른다.
다른 앱은 같은 장치에서 각자 버퍼를 고른다. 엔진의 선택은 엔진 쪽 지연과 안정성에만 영향을 주며, 입력 지연은 측정값으로 보고한다.
외부 앱·물리 장치 버퍼와 PipeWire 그래프 quantum을 장치별 독립 값으로 약속하지 않는다.
DSP 최대 slice·native callback quantum·공유 버퍼 용량을 실제 지연이나 OS 전체 버퍼로 표시하지 않는다.

### 수동 진단 리포트

사용자가 지정한 `dump.json` 하나에 허용된 버전·OS·아키텍처·장치 형식·실행 상태·수치 카운터를 저장한다.
최대 256KiB, 장치 요약 최대 64개, 동시 내보내기는 하나다. 취소 시 파일을 만들지 않고 같은 위치는
OS 덮어쓰기 확인 후 원자적으로 교체한다. 자동 저장·업로드·앱 내부 축적은 하지 않는다.

오디오·메모리·원시 로그·보안/인증 정보·사용자 경로·장치 이름/ID·그래프·앱 목록은 제외한다.
조회 실패는 unavailable로 표시하며 진단 때문에 오디오를 시작하지 않는다.
`sampleFaults`는 소스·노드 입력·노드 출력의 비정상 샘플 교체 수와 영향받은 블록 수를 고정 크기 포화 카운터로 보관한다.
정상 입력 뒤에도 누적값은 유지하고 발생별 이벤트나 오디오를 쌓지 않는다. 미지원 실행부의 값을 0으로 꾸미지 않는다.

## 앱 기능과 사용 흐름

1. 그래프에 앱·물리/가상 입력·처리·출력·레코더를 추가하고 포트를 연결한다.
2. Options에서 게인·채널·장치·효과 설정을 바꾼다. 선택한 그래프와 실행 상태는 독립적이다.
3. 노드 Off는 처리를 제외하고 신호를 차단한다. Mute는 처리를 유지하며 출력을 끈다. 효과 bypass는 원음을 통과시킨다.
4. 녹음을 시작·일시정지·재개·정지하고 작업 공간을 `.mix` 파일로 저장한다.

유료 앱의 여러 그래프는 동시에 실행할 수 있다. 장치 identity별 native 소유자는 하나이며
OS playback과 그래프 출력을 한 번만 합쳐 OS capture와 그래프 입력에 제공한다.
각 그래프의 routing·gain·layout은 독립적이고 참조 하나를 제거해도 다른 참조를 끊지 않는다.
마지막 그래프 참조를 제거해도 Driver 장치는 유지한다. 사용자 피드백 경로는 임의로 바꾸지 않으며 인과적·유한 처리를 유지한다.
앱 출력 차단은 MixRelay가 소유한 전달 경로만 제어한다. 타 앱·시스템 기본 출력은 자동 변경하지 않고 외부 변경 시 소유권을 해제한다.
UI·API·Stream Deck은 같은 제어 경로를 사용한다. Stream Deck은 그래프·노드별 전원·음소거·볼륨·녹음을 제어한다.

### 녹음

한 번의 녹음은 RF64 `.wav` 파일 하나로 작성하며 용량에 따른 롤링은 하지 않는다.
PCM16·PCM24·Float32와 샘플레이트를 선택하고 녹음·일시정지 중 형식은 변경하지 않는다.
레코더는 1–8채널, 기본 2채널, 기술적 세션 상한 16개다. 무료는 레코더 1개·최대 2채널이다.
무료 2시간 한도는 실제 기록한 누적 프레임으로 검사하며 Pause 시간은 제외한다.
한도에 도달하면 파일만 정상 마무리하고 오디오 라우팅은 유지한다. 유료에는 이 시간 한도를 적용하지 않는다.

### 내장 처리와 프리셋

| 처리 | 제공 범위 |
| --- | --- |
| 컴프레서·리미터 | 입력/출력 피크, makeup 이전 실제 감쇠량, threshold/ceiling |
| EQ·필터 | 3개 피크 밴드의 20Hz–20kHz·Gain ±24dB·Q 0.1–10, 하이패스·로우패스 |
| 게이트·익스팬더 | 문턱 이하 차단·감쇠 |
| 채널 유틸리티 | 두 채널 평균 모노 합산, 단일 채널 양쪽 출력, 좌우 교환, 극성 반전 |
| 게인·팬/밸런스 | 게인, 모노의 스테레오 배치, 스테레오 밸런스 |
| 딜레이 | ms 지연, 채널별 에코·핑퐁 |
| 더킹 | 별도 mono 제어 입력으로 감쇠하며 제어 신호는 출력에 합치지 않음 |
| 리버브·코러스 | 자체 기본형·조밀형 잔향, 코러스 |

노이즈 억제·LUFS는 이번 범위에 포함하지 않는다. 높은 미터 색을 클리핑 판정으로 대신하지 않는다.
리버브·코러스·더킹의 실제 버스/채널 범위와 공통 DSP의 64채널 지원은 구분한다.

단일 리버브 프리셋은 작은 방·스튜디오·홀·가라오케·터널·어항,
딜레이는 짧은 에코·슬랩백·보컬 에코·가라오케·긴 에코·핑퐁을 제공한다.
체인 프리셋은 가라오케·터널·어항·라디오·더블 보컬 등을 제공한다. 체인 삽입은 Undo 하나로 되돌리고
기존 연결을 임의로 바꾸지 않는다. 실제 파라미터·연결·사용자 수정을 저장하며 수정 후 프리셋 이름으로 값을 대신하지 않는다.
외부 IR·샘플 설치를 요구하지 않고 특정 실제 공간의 정확한 재현을 약속하지 않는다.

DSP는 기존 의존성과 자체 구현을 우선 사용한다. 새 외부 코드·자산은 버전·출처·라이선스·상용 배포 조건·고지 의무를 확인한다.
단순 처리를 위해 효과별 패키지·런타임·호스트를 늘리지 않는다. 구현 근거는 [공간 효과](design/builtin-spatial-effects.md)에 둔다.

### 공통 안전·이력 정책

- 소스 수용·노드 입력·노드 출력에서 NaN/Inf를 0으로 바꾸고 정상 유한 샘플의 비트를 보존한다.
  비정상 입력 뒤 정상 입력을 계속 처리하며 경계별 교체 수를 `sampleFaults`로 누적한다.
- 이력은 `render/history.rs`의 공통 경로로 관리한다. 같은 종류·채널·포맷·입력 경로의 파라미터 편집은 보존하고
  직접/상위/sidechain 경로·종류·채널·포맷 변경은 초기화한다. 입력 불연속은 도달하는 이력만, 전역 시계 단절은 전체를 초기화한다.
- Off는 이력을 무효화하고 Mute·bypass는 처리를 유지한다. 효과 파라미터와 bypass는 5ms로 전환한다.
  수동 딜레이와 자동 플러그인 지연 보상은 별개다.
- 변경 자원은 비실시간에서 준비하고 같은 revision의 블록 경계에서 교환한다.
  콜백은 무할당·무잠금·무로그·무파일 I/O·유한 실행을 유지한다. 제거·실패·종료에서 소유 자원을 회수한다.
- 주요 PCM 버퍼는 공통 fallible 예약을 사용한다. 실패하면 부분 할당을 회수하고 활성 오디오를 유지한다.
  Driver의 활성·해제 대기·준비 중 Mapping은 총 256개, 고유 공유 영역은 총 1GiB로 제한한다.
  재사용 영역은 중복 계산하지 않고 commit/cancel·peer 수용에 필요한 목록도 미리 예약한다.
- 방어 검증은 유닛 테스트에서 실패를 주입한다. 실제 시스템 메모리 고갈·강제 연결 단절 시험은 수행하지 않는다.
  소유권·한도·실패 처리를 공통 경계에서 관리하며 별도의 압박 감시나 주기 재연결 체계는 두지 않는다.

### 외부 플러그인

AU/AUv3는 macOS, VST3·CLAP은 macOS·Linux, LV2는 Linux에서 기존 호스트와 공식 API로 연결한다.
SDK를 재구현하거나 모든 채널/버스 조합을 탐색하지 않는다. 악기를 효과 목록으로 제공하지 않는다.
다중 플러그인·다채널·sidechain·64→16 매핑을 지원하되 실제 플러그인이 거부한 형식은 적용하지 않는다.
worker와 editor는 같은 인스턴스를 사용하고 장애·제거 후 회수한다.

## 화면과 조작

시스템·라이트·다크 테마를 제공하며 시스템이 기본이다. 사용자 선택은 로컬 저장·복원하고 저장 실패 시에도 현재 세션에서 전환한다.
DSUB 오프화이트·그래파이트 표면과 정보·긍정·주의·오류 역할을 사용한다. 색과 상태명·아이콘을 함께 제공한다.
시각 값과 컴포넌트 계약은 [디자인 시스템](design-system.md)에 두고 Core부터 수정한다. 커스텀 테마 편집·로딩은 별도 범위다.

- 하단 왼쪽은 앱 버전·확인된 인증 상태와 라이선스 진입점, 오른쪽은 전체 오디오 일시정지/재개 아이콘이다.
  전환 중 크기·아이콘을 유지하며 설명은 툴팁·접근성 이름에 둔다. 장치 형식·진단 카운터는 해당 설정이나 진단에 둔다.
- native About는 제품 정보·지원·접힌 약관을 제공한다. 업데이트는 헤더, 장치 설정은 노드 Options에 둔다.
- 시작 시 Driver 연결과 엔진 응답을 확인한 뒤 작업 화면을 연다. 연결 중은 중립 로딩,
  실패·미설치·호환 불일치는 원인과 재시도·설치 행동을 표시한다.
  연결 단절 시 미저장 편집을 보존하고 자동으로 오디오를 재시작하지 않는다.
- 기본 노드는 이름·신호·즉시 조작, 세부 설정은 Options에 둔다. 작업 화면은 창에 고정하고 목록·설정만 내부 스크롤한다.
- EQ는 로그 주파수/dB 응답 그래프와 세 조작점을 기본 면에, 주파수·Gain·Q 표는 공통 Options에 둔다.
  가로/세로 변경은 같은 배치·Undo 단위다. 노브는 사용하지 않으며 기본 중심값은 150Hz·1kHz·6kHz다.
- 다른 반복 연속값은 Core 노브·숫자 조작, 단일 게인은 ValueSlider를 사용한다.
  실제 단위의 키 증분·비선형 스케일·미세 조정·직접 입력을 공통 계약으로 제공한다.
- 효과 기본 면은 bypass 조작 하나다. 외부에서 적용된 Off/Mute는 해제할 복구 버튼으로 표시한다.
  컴프·리미터의 감쇠를 입출력 피크 차이로 추정하지 않고 엔진 계측을 표시한다. 미수신 계측은 빈 레일·대시다.
- 채널 묶음 선택은 한 노드의 출력에 한정한다. Shift로 추가하고 목적지 용량/오프셋에 맞춰 연결한다.
  드래그 중 CH 범위·개수를 표시하고 Esc로 취소·선택 해제한다.

실행부의 확인된 설정이 화면과 다음 조작의 기준이다. 외부 변경은 자동 반영하고 실제 바꾼 항목만 최신 문서에 병합한다.
단순한 revision 갱신이나 병합 가능한 외부 변경에는 불러올 문서를 고르게 하지 않는다.
명확한 revision 거부는 제한 시간 안에서 최신 문서에 실제 편집한 항목만 재병합해 재시도한다.
결과가 불확실한 명령은 자동 반복하지 않으며 편집을 보존하고 확인 후 재시도한다.
자동 해결할 수 없는 지속 충돌에만 편집본 적용·편집 취소 선택을 제공한다.
삭제·교체된 노드를 오래된 편집본으로 되살리지 않는다. 외부 변경으로 무효화된 Undo는 초기화한다.
오디오 설정과 배치는 분리하며 일시적인 조회 실패 후 읽기 전용 복구를 계속한다.

### 키보드와 접근성

노드 선택의 Tab 대상은 바깥 노드 하나이며 실제 버튼·입력은 별도 대상이다.
읽기 전용 미터에는 Tab을 추가하지 않는다. 모달은 Core Dialog의 포커스 순환·복귀·busy 계약을 사용한다.
행동마다 포커스 소유자를 하나로 정하고 역할·이름·상태·실제 키 실행을 확인한다.
좁은 화면·긴 번역·스크린리더와 채널 연결의 키보드 대체 경로는 [접근성 계약](design/interaction-accessibility.md)에 따른다.
UI 검증은 `pnpm check:ui-quality`와 `pnpm --filter @mixrelay/control-ui check`를 사용한다.

## 설치와 판매

### 단일 제품 통합 기준

MixRelay는 무료·유료 기능을 포함한 하나의 제품·실행 앱·버전으로 통합한다.
Driver 장치 관리 기능도 같은 MixRelay에서 제공한다. OS 드라이버와 백그라운드 오디오 실행부는
편집 앱 종료 후 오디오를 유지하기 위한 내부 구성요소다.
설치 파일은 구성요소 선택 없이 MixRelay 전체를 설치하며 별도 Driver 실행 앱을 제공하지 않는다.
앱·Driver 중 어느 부분이 변경돼도 같은 MixRelay 버전과 전체 설치본으로 업데이트한다.
사용자에게 앱·Driver별 버전·다운로드·업데이트 선택을 요구하지 않는다.
업데이트는 기존 장치·그래프·설정·녹음·인증을 보존한다.

출시 전 제품 버전은 `0.1.0`을 유지한다. Cargo workspace·앱 manifest·Tauri가 같은 버전을 사용하며
`pnpm product:version`으로 대조한다. 실제 설치본 검증과 소스·패키지 검사는 구분한다.

2026-10-12 소스 통합과 macOS 전체 Developer ID 서명 PKG 빌드를 완료했다.
완성 패키지의 단일 고정 설치·모든 구성요소 0.1.0·Universal 2·게시자 서명을 확장 검사했다.
롤백·데이터 보존은 소스 fixture로 확인했다. 실제 호스트 설치·업데이트와 Linux 배포판의
전체 패키지 설치 검증, 공증·공개 배포는 아래 설치·공개 파일 검증 범위에 남는다.
검사 근거는 [검증 현황](validation/current.md)을 따른다.

제품 파일은 아직 공개 배포하지 않았다. 웹사이트 직접 다운로드를 준비하며 기본 Driver 사용에 구매 인증을 요구하지 않는다.
사용자가 SDK·별도 런타임·서비스를 직접 설정하게 하지 않는다. 플랫폼별 절차는
[macOS](../packaging/macos/README.md)·[Linux](../packaging/linux/README.md)에 둔다.

- 설치 파일은 편집 앱·실행부·엔진·가상 장치를 함께 설치한다. Driver 선택 단계와 별도 Driver 앱은 없다.
  macOS는 하나의 native 트랜잭션으로 기존 파일을 백업·교체하고, 실패 시 같은 트랜잭션에서 기존 파일을 복원한다.
- 업데이트는 장치·그래프·설정·녹음·인증을 보존한다. 시작 시·24시간마다 조회하고 수동 확인을 제공한다.
  MixRelay 하나의 설치 버전과 게시 버전을 표시하고 미게시/실패를 최신으로 표시하지 않는다.
  다운로드 시 목록을 다시 확인해 링크만 열며 자동 설치하지 않는다.
- 제품 제거는 앱·장치·루프백·실행부를 함께 정리한다. 저장 데이터 삭제 옵션은 기본 미선택이며,
  업데이트·설치 복구는 이 옵션을 실행하지 않는다. 외부 프로젝트·녹음은 보존한다.
  실패·취소에서도 재실행·재제거할 수 있어야 하며 실패·취소한 제거는 인증을 지우지 않는다.
- macOS는 기본 Installer의 약관→계속→동의 흐름과 Developer ID 서명·공증을 사용한다.
  MixRelay PKG에 `Uninstall MixRelay`를 포함한다. 제거는 서명된 앱을 확인하는 on-demand 도우미의 고정 작업으로 수행하고
  인증 취소 전에는 상태를 변경하지 않는다. 설치 화면의 제거 선택·별도 제거 PKG·트레이 제거는 제공하지 않는다.
- Linux는 패키지 관리자 경로를 사용한다. 모든 패키지는 제품별 약관·변경 내역·제3자 고지를 포함한다.
- 공개 설치 파일은 제품별 `x.y`의 최신 패치만 보관한다. 새 패치 게시 확인 후 이전 패치를 다운로드 목록에서 제거한다.

Linux 오디오는 정상 사용자 PipeWire 세션에서 실행한다. Proxmox 등 x64 Linux VM에서도 정상 동작한다.
Docker 컨테이너·Docker 기반 VM에서는 제품 오디오를 실행하지 않는다. 해당 환경의 PCM 누락·되돌림은
비지원 실행 환경의 제한으로 안내하며 해결 작업으로 두지 않는다. Docker는 빌드·코드 검사에 사용할 수 있다.

App Store·AudioDriverKit 재작성·BPM·MIDI·새 JACK/ALSA 백엔드는 이번 범위에서 제외한다.
성능 비교 방법은 [측정 절차](performance/audio-engine-render-baseline.md)에 둔다.

### 인증 확인·해제

인증은 Driver가 관리하고 앱은 키 입력·상태·수동 확인·기기 해제 UI를 제공한다.
OS 인증 저장소를 사용하며 저장된 활성화와 구매 메이저 버전을 구분한다.

- Driver 시작·앱 최초 연결의 자동 확인은 백그라운드에서 하나로 합치고 최근 시도 후 24시간 내 반복하지 않는다.
  실행 중 별도 네트워크 타이머나 즉시 재시도는 두지 않는다. 수동 확인·활성화·해제는 별도다.
- 응답을 기다릴 때 기존 유효 인증을 사용한다. 연결 실패·시간 초과·429·5xx는 무알림으로 처리하고 인증을 지우지 않는다.
  온라인 성공만 오프라인 기간을 갱신하며 재시작·실패로 기간을 연장하지 않는다.
- 만료·회수 시 진행 중 오디오·녹음을 끊지 않는다. 새 유료 작업은 유효 인증을 요구하며 해당 조작/인증 창에서 상태를 안내한다.
- 기기 해제는 해당 활성화만 정리하고 다른 컴퓨터·키 전체를 취소하지 않는다. 원격에서 이미 해제됐으면 로컬도 정리한다.
  재설치와 서버 활성화 해제는 별개이며 기존 컴퓨터를 사용할 수 없을 때 지원 복구 경로를 제공한다.
- 활성화 무제한은 제공자 설정의 `activation_limit: null`을 사용한다.
  네트워크 실패를 환불·회수로 해석하거나 불확실한 응답 뒤 새 활성화를 반복하지 않는다.

### 그래프 인스턴스 표시 이름

그래프 노드의 이름 더블클릭, F2, 단일 노드 메뉴로 그 인스턴스의 표시 이름을 변경한다.
별칭은 그래프 표시 메타데이터 `GraphLayout.nodeLabels`에 UI ID별로 저장·복원하며 128자 이내로 trim한다.
별칭이 없을 때 입력은 빈 값이고 원래 이름을 placeholder로 표시한다. 필드 이름은 유지하며 원래 이름의 부연설명을 반복하지 않는다.
비우면 원래 이름을 사용한다. 앱·장치의 실제 이름, 캡처 selector, runtime label, 노드 ID와 오디오 revision은 유지한다.
같은 앱을 참조하는 노드 두 개나 duplex 입력·출력 카드는 독립된 별칭을 가질 수 있다.
창·탭별 캡처 분리는 이 기능의 범위가 아니다. 저장 실패는 별칭 초안을 유지하고 기존 메타데이터 재시도를 사용한다.
