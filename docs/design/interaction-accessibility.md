# 조작·포커스·접근성 계약

제품 지원 범위와 잔여는 [product.md](../product.md#키보드와-접근성)에 기록한다. 이 문서는 Core 컴포넌트와 Feature가 지켜야 할 구현 계약이다.

## 구분

- **포커스**: 지금 키보드로 조작할 대상. 실제 행동이 있는 요소에만 Tab 정지점을 둔다.
- **선택**: 명령이 적용될 대상. Tab 이동으로 실행 상태나 선택을 바꾸지 않는다. 포커스 표시와 선택 표시는 구분한다.
- **접근성**: 이름·역할·값·상태·관계를 읽고 기능을 조작할 수 있는 것. Tab 대상이 아닌 텍스트·미터·상태도 해당한다.

## 요소별 계약

## 구현 규칙

그래프의 노드·연결선 설명, 이동 안내(live region), 연결선·포트·미터 이름은 현재 언어의 번역 문구를 사용한다. React Flow 기본 영어 문구나 내부 ID를 노출하지 않는다. Core `AudioGraphCanvas`가 `ariaLabelConfig`와 연결선 이름을 소유하고, Feature는 포트 묶음 이름을 `GraphPresentation.ports`로 전달한다.

1. 같은 행동에 포커스 소유자는 하나다. 그래프 안 `AudioNodeCard`는 `onSelect`를 생략해 표시용으로 렌더한다. 독립 선택 카드에만 실제 `onSelect`를 전달한다.
2. DOM 읽기 순서를 Tab 순서로 사용한다. 양수 tabindex·빈 래퍼·동작 없는 버튼·포커스 없는 가짜 button 역할을 만들지 않는다. 메뉴 등 복합 위젯 내부 이동은 해당 패턴을 따른다.
3. 노드 내부 컨트롤은 `nokey` 경계로 그래프 단축키와 분리한다. 텍스트 편집·슬라이더 조절·메뉴 조작이 노드 이동/삭제를 일으키면 결함이다.
4. 키보드 포커스에는 중립색 1px 표시 하나를 둔다. 입력은 기존 경계 색만 바꾸고 바깥 링을 겹치지 않는다. 버튼·노드는 키보드 포커스 윤곽을 사용한다. 선택 포트는 기본 크기·간격을 유지하고 색만 바꾼다. 프로그램 포커스 전용 배경을 일반 Tab 대상으로 만들지 않는다.
5. 닫기·삭제·숨김 이후 포커스는 트리거 또는 인접한 남은 조작 대상으로 복귀한다. body로 유실하거나 일반 화면에서 Tab을 가두지 않는다.
   그래프 복구 버튼이 applying 전환·복구 완료로 제거되면 Core `useRemovedFocusReturn`이 해당 복구 영역의 소유자만 추적하고 기존 그래프 이름 입력으로 복귀한다. 연결된 대상·명시적 blur·다른 조작으로 이동한 포커스는 유지하며, 작업 영역이 교체·unmount되면 이전 영역으로 복귀하지 않는다. 노드 헤더의 인접 버튼 복귀와 소유권을 겹치지 않는다.
6. native button/input을 우선한다. ARIA 이름만으로 키보드 구현을 대신하지 않는다. disabled는 이유를 읽을 수 있게 하고, 작업 완료/실패만 필요한 시점에 알린다.
   반복되는 삭제·노드 설정·바이패스·플러그인 에디터·녹음·폴더 행동의 접근성 이름에 그래프/노드의 표시 이름을 포함한다. 비밀번호 표시/숨기기는 필드 이름을 포함한다. Core는 대상과 행동을 조합하고 Feature는 실제 대상 이름·명령을 전달한다. 공통 Tooltip은 기존 버튼에 연결하며 같은 이름의 native title이나 wrapper Tab 대상을 추가하지 않는다.
   추가 버튼은 보이는 +와 실제 aria-label, hover/키보드 focus 툴팁을 제공한다. 메뉴를 열고 Escape로 닫아 같은 트리거로 복귀하며 추가 Tab 대상은 만들지 않는다. 필드 placeholder는 기본값의 단서이며 보이는 label·접근성 이름과 분리한다.
   노드 제목줄의 Off → Mute → Options는 Core의 같은 DOM 순서를 사용한다. 내장 효과는 Off·Mute 대신 바이패스 → Options 순서를 사용한다. 저장값·외부 명령으로 Off·Mute인 효과에만 그 상태를 해제하는 복구 행동을 먼저 제공한다. Options 트리거와 설정 패널은 `aria-expanded`·`aria-controls`로 연결한다. 제목줄의 배치 슬롯은 Tab 대상이 아니며, 레코더는 이후 Record/Pause/Stop과 펼친 설정으로 이어진다.
7. 모든 모달은 Core `Dialog`를 사용한다. 닫힘·조건부 unmount 모두 포커스를 복귀시키되, 사용자가 이미 다른 조작 대상으로 이동했다면 빼앗지 않는다. busy 중에는 Esc·바깥 클릭·닫기 동작을 막는다.
   폼의 DOM·Tab 순서는 필드 → 필요한 오류/설명 → 하단 취소 → 저장/확정이다. 하단은 Core FormActions로 우측 정렬하며, 취소 버튼은 type=button으로 제출을 실행하지 않는다. 이름·생성·확인 폼은 헤더에 중복 닫기 정지점을 두지 않는다. 정보 모달의 헤더 닫기는 유지한다.

노드 표시 이름 편집은 이름 텍스트의 더블클릭, 바깥 노드 그룹의 F2, 단일 노드 컨텍스트 메뉴로 연다. 제목 텍스트에 추가 Tab 정지점을 만들지 않는다. 모달 필드와 제출은 Core NameDialog가 소유하고 그래프 이동·삭제 키를 실행하지 않는다. Escape는 취소, 빈 제출은 원래 표시 이름을 복원하며 닫으면 같은 바깥 노드 그룹으로 돌아온다. 실제 앱/장치 식별자와 오디오 설정은 변경하지 않는다.

채널 연결의 키보드 경로는 노드 바깥 그룹이나 그래프에서 Shift+F10·ContextMenu 키로 보조 클릭과 같은 컨텍스트 메뉴를 열고 '채널 연결…'을 고른다. 노드 내부 컨트롤·입력 필드·IME 조합·키 반복은 메뉴를 열지 않는다. 노드에서 열면 모든 출력 채널 범위, 선택한 출력 포트에서 열면 그 선택을 유지하며 '채널 범위로 지정'으로만 범위로 바꾼다. Core ChannelConnectionDialog는 포인터 드래그와 같은 `mapChannelConnections`·`planChannelConnections`로 각 쌍과 건너뛴 채널의 사유(대응 입력 없음·이미 연결됨·피드백 루프·사용 불가)를 미리 보이고, 요약만 polite status로 알린다. 고른 대상·첫 채널이 그래프 변경으로 사라지면 다른 채널로 자동 대체하지 않고 다시 고르게 한다. 경계 자기 연결이 가능한 노드는 자신도 대상으로 제공한다. 제출 때 현재 그래프로 다시 검증해 한 번의 runtime commit(실행 취소 한 단계)으로 연결하고, 닫으면 출발 노드 바깥 그룹으로 돌아온다. React Flow의 Delete/Backspace는 문서 전역 키이므로 키 추적은 유지하되 `onBeforeDelete`에서 포커스가 그래프 밖(대화상자 등)이면 삭제를 거부한다.

## 변경 완료 기준

Core 변경은 역할·이름·상태·Tab 대상 여부를 회귀 검사한다. Feature는 실제 명령·busy/오류·포커스 복귀를 검사한다. Storybook에서 순방향/역방향 Tab, 실제 키 실행, 내부 컨트롤과 그래프 키 충돌, 좁은 폭·긴 번역을 확인한다. 보조 기술의 실제 읽기는 별도 검증하며 자동 검사와 구분한다.

근거: [WAI-ARIA APG 키보드 인터페이스](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/), [APG 미터 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/meter/), [WCAG 2.2 키보드 기능](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html). 위 요소 배분과 그래프 키 계약은 MixRelay의 제품 결정이다.

장치 설정의 포커스 순서는 이름 → 공통 채널 수 → 샘플레이트 → 비트 심도다. 지원값이 하나뿐이고 현재 값과 같으면 변경 선택기는 disabled다. 불일치에서 공통 값을 선택할 수 있는 경우는 활성 상태로 유지한다. 키보드 선택·오류 설명도 노드와 드라이버 설정이 같은 Core 계약을 따른다. 그래프 목록은 끝에서도 앱 바깥으로 스크롤을 전달하지 않는다.
