# Recorder output

## Contract

- Recorder creation defaults to two channels; configuration allows 1–8 channels.
  Transport buttons are icon-only immediately below the meter, with an elapsed
  `HH:MM:SS.mmm` display. File/rate/encoding/channel settings use the existing
  collapsible Options presentation.
- An output node records its final routed/mixed input, without becoming a native
  audio device or introducing a new playback clock.
- Record defaults to the interactive user's OS Desktop with a timestamped,
  per-renderer-sequenced filename, or an absolute user-selected path. Existing
  files are never overwritten. Pause drains accepted audio and excludes paused time;
  Record resumes the same take. Stop drains, finalizes and closes the WAV.
- The file's sample rate and encoding are fixed for a take. Input-rate changes
  are converted at the recording boundary; the source and monitor device formats
  are not retuned. Integer PCM16/PCM24 use final-stage TPDF dither. Float32
  preserves floating-point samples without integer clipping.
- File I/O and conversion belong to an owned writer thread, not the render
  callback. A recording failure must not stop hardware monitoring.
- Recording belongs to the graph ID and node ID, not the currently selected
  graph. Closing the desktop does not stop it. Final node retirement and orderly
  engine shutdown finalize the file. Unexpected process termination/power loss
  is not a guaranteed finalized recording.
- Stopped channel reconfiguration prepares a separate channel-geometry transport
  while the previous plan still exists. Discarding that preparation must not
  orphan the previous recorder. Recording/paused channel changes are rejected
  by both the UI and the engine.
- This implementation writes RIFF WAV, not RF64. Before the 32-bit size limit,
  it finalizes the current file and continues at the next complete audio frame
  in `name-002.wav`, `name-003.wav`, etc. Take time, SRC and dither state continue
  across parts. An exact-boundary Stop does not create an empty next file.
  Collision, permission and disk errors stop recording with the failing path;
  existing files and successfully finalized earlier parts are retained.

## Desktop default and automatic file rollover follow-up

- Desktop resolution belongs to the Tauri user session, not the background
  engine's working directory. The native resolver does not create or reserve a
  file; the recorder's exclusive open remains the authority. Unsupported Desktop
  resolution is visible and manual destination selection remains possible.
- Automatic destinations refresh after Stop or Failed, including reopening a
  failed recorder. A manual destination is never replaced by a late suggestion.
  Pause/Resume retain the active take's original path and format.

## Bounded memory and performance evidence

See `crates/audio-recorder/README.md` for serialized trial conditions and raw
results. At stable 32-frame callbacks, partial-packet packing uses all 32,768
preallocated frame slots rather than wasting seven eighths of that PCM storage.
A native Rust regression withheld writer servicing for 500 ms, then verified
all accepted eight-channel PCM and the final 96-kHz WAV without an overrun.
This is a file-writer backlog budget, not extra hardware-monitor latency.

The debug DSP optimization/preparation stage reduced the measured process CPU
mean from 1.867 to 0.943 seconds for the paced ten-second stereo probe. This
includes an explicitly recorded recorder-crate dev opt-level change. Packing
under the same build policy measured 0.937 seconds, a 0.7% difference treated as
noise, not a CPU improvement claim. Neither probe proves end-to-end deadlines.
