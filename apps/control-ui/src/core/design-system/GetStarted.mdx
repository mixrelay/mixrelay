# 시작하기

MixRelay 저장소에서 기존 Core를 찾아 제품 화면에 사용하는 절차입니다. 컴포넌트는 앱 소스에 포함되어 있으며 별도 npm 라이브러리로 배포하지 않습니다.

## 실행

저장소 루트에서 실행합니다. Node·pnpm 버전은 루트 `package.json`의 `engines`와 `packageManager`를 따릅니다.

```sh
pnpm install --frozen-lockfile
pnpm storybook
```

`http://localhost:6006`에서 Overview부터 읽고, Components에서 목적이나 컴포넌트 이름으로 검색합니다. 개발 앱 실행은 `pnpm --filter @mixrelay/control-ui dev`입니다.

## 컴포넌트 선택

| 과업 | 시작할 계약 | 다음 확인 |
| --- | --- | --- |
| 문구로 명령 실행 | ActionButton | 일반 quiet, 최종 제출 strong, loading·disabled |
| 이름·문장 입력 | TextField | 레이블·현재 값·오류·readOnly; Feature의 상태 갱신 |
| 수치·단위 입력 | NumericValueControl / ParameterField | 실제 단위·step·범위와 Knob 부모의 compact 계약 |
| 현재 상태 표시 | StatusBadge / InlineNotice | 의미별 tone, 새 실패의 alert, 색 이외의 문구 |
| 값·명령 선택 | SelectField / HierarchicalMenuButton | 값 선택과 실행 명령의 구별, 방향키·닫기·복귀 |
| 폼 조합 | Stack / FormActions | 입력 순서·오류 관계·제출 소유자 하나 |
| 그래프 편집 | RoutingWorkspace의 기존 Feature | 실제 포트·실행 상태·자동 병합·실패 복구 |

## 예시 읽는 순서

1. 독립 문서에서 목적·사용 구분과 정확한 공개 타입을 확인합니다.
2. 각 계약의 Playground Controls에서 지원 속성을 바꿉니다. 예시의 초기 args는 Core의 기본값과 구별합니다.
3. 고정 상태 예시에서 disabled·busy·오류 등 필요한 조합을 확인합니다.
4. 조합 예시와 실제 소비자에서 값·요청·오류를 소유하는 계층을 찾습니다.

공개 계약 61개 모두 각 독립 문서에 실제 Core export를 연결한 Playground·API·구현 기본값·상태·사용례를 제공합니다. <a href="/?path=/docs/design-system-components--docs" target="_top">컴포넌트 목록</a>에서 목적과 지원 상태로 찾습니다. 메뉴·모달은 실제 트리거를 사용하고 Provider는 같은 Context 소비자를 함께 렌더합니다. 공개 props가 없는 ThemePicker·ProductHeading은 Context·조합 계약을 표시합니다.

## 앱과 같은 환경

앱과 Storybook은 `I18nProvider`·`MixRelayProvider`를 공유합니다. 앱의 기존 루트 아래에서는 Provider를 다시 중첩하지 않고 Core만 import합니다. 독립 렌더 환경은 `src/core/i18n`과 `src/core/theme/MixRelayProvider`를 사용합니다. 전역 글꼴·역할 토큰은 Provider의 공통 CSS에서 불러옵니다.

Storybook toolbar의 theme·locale은 Canvas의 환경입니다. 한국어 설명문과 문서 테마는 DocsLayout이 소유합니다. 앱의 저장된 테마를 바꾸는 설정 화면으로 해석하지 않습니다.

## 입력·제출 조합

이 예시는 같은 TextField·SelectField·InlineNotice·FormActions·ActionButton으로 구성한 로컬 폼입니다. 입력 변경과 제출 결과는 예시의 React 상태이며 실제 장치에 저장하지 않습니다. 해당 소스는 `src/core/ui/Composition.stories.tsx`의 `FormFlow`입니다.

제품에서는 Feature가 기존 포트에 요청하고 실제 응답으로 상태를 갱신합니다. 공통 치수·색·글꼴은 Core에서 가져오며 화면 CSS로 재정의하지 않습니다.
