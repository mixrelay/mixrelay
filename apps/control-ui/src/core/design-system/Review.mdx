# 변경과 검수

## 변경 순서

1. Foundations와 기존 컴포넌트·패턴·페이지에서 규격의 소유자를 찾습니다.
2. 값은 토큰, 공통 상태 표현은 테마, 공개 속성과 조작은 Core에서 변경합니다.
3. Feature/Screen 소비자를 같은 계약에 맞추고 해당 문서와 실제 스토리를 갱신합니다.
4. 자동 검사와 아래 화면·키보드 검수를 수행하고 수행 환경을 기록합니다.

## 검수표

| 관점 | 확인 | 결함의 예 |
| --- | --- | --- |
| 역할과 정보 | 이름·값·단위·상태의 계층이 분명한가 | 화면 선택을 실행 성공으로 표시 |
| 상태 | 지원하는 독립 상태와 조합이 구별되는가 | Off·Mute·앱 일시정지·녹음 일시정지를 같은 상태로 표시 |
| 시각 규격 | 실제 역할 토큰·글꼴·밀도를 소비하는가 | 사용처에서 공통 버튼의 크기·색을 덮어씀 |
| 키보드 | 순방향/역방향 Tab, Enter/Space, 방향키, Esc가 계약대로 실행되는가 | 행동 하나에 Tab 대상 둘, 노브 조작이 노드 이동을 실행 |
| 포커스 | 열기·닫기·제거·실패 후 다음 행동이 가능한가 | 삭제된 조작의 포커스가 body로 유실 |
| 접근성 | 이름·역할·현재 값·상태·관계를 제공하는가 | 색으로만 오류 전달, 모달 제목 연결 누락 |
| 테마 | Light/Dark/System의 기능 경계·글자·포커스가 읽히는가 | 장식 경계와 입력 경계를 같은 대비로 취급 |
| 콘텐츠 | 390px 폭, Pseudo와 11개 언어, 긴 이름·단위에서 잘리는가 | 재시도 버튼이 메시지를 가리거나 숫자가 다른 단위와 분리 |
| 과업 | 빈 상태·대기·실패·복구와 반복 조작을 설명하는가 | 불확실한 상태를 성공으로 표시하거나 마지막 유효 값을 삭제 |

문서의 테마 전환과 실제 Canvas 테마 전환을 각각 확인합니다. 숫자와 단위는 Mono, 일반 문장과 명령은 Sans를 사용합니다. 좁은 화면에서도 화면 바깥 스크롤과 내부 목록·그래프 스크롤을 구분합니다.

## 자동 검사

```sh
pnpm check:ui-quality
pnpm --filter @mixrelay/control-ui check
```

UI 검사는 Core 경계, 타입, 회귀·coverage, 앱 및 Storybook 빌드를 포함합니다. 실패하면 어느 단계와 기준이 실패했는지 기록합니다. 일부 단계의 통과를 전체 검사의 통과로 표시하지 않습니다.

## 검증 범위

| 근거 | 입증하는 것 | 별도 확인이 필요한 것 |
| --- | --- | --- |
| 타입·경계·빌드 | 소스 계약과 번들 구성 | 사용자의 실제 과업 완료 |
| 테스트·Storybook 로컬 상태 | 특정 입력과 상태에서의 컴포넌트 동작 | 실제 오디오·장치·파일의 성공 |
| 자동 접근성 검사 | 검사기가 찾을 수 있는 DOM·대비 결함 | 실제 스크린리더 읽기와 모든 키보드 과업 |
| 브라우저 화면·키 실행 | 확인한 테마·폭·언어·상태의 렌더와 동작 | 설치본·OS·드라이버 조합 |
| 실제 설치본·보조 기술 확인 | 기록한 환경에서 실제 수행한 결과 | 시험하지 않은 환경 |

미확인 항목을 완료로 표시하지 않습니다. 제품의 잔여 검증과 진행 상태는 `docs/product.md`에 기록합니다. 문서 예시의 개수로 검증 범위를 추정하지 않습니다.

## 리뷰 기록

날짜별 검수 기록은 저장소의 `docs/validation/design-system-reviews.md`에 보관합니다. 기록의 개수·coverage 수치는 그 시점의 값입니다. 현재 계약·공개 export 수와 검사 결과는 `pnpm --filter @mixrelay/control-ui check`의 출력이 기준입니다.
