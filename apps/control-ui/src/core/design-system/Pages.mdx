# Pages

MixRelay의 작업 화면·연결 진입·라이선스·제품 정보를 실제 코드로 문서화한다. 페이지는 Core의 역할 토큰과 컴포넌트를 소비하며, 별도의 색·서체·조작 규격을 소유하지 않는다.

`App/Workspace`는 실제 App에 결정적 preview 포트를 연결한다. 그래프·응답·계측은 fixture이며, 실제 오디오·장치·파일·온라인 인증은 변경하지 않는다. 표시와 편집 경로는 제품의 같은 Feature를 통과한다.

## 1. 페이지 구성과 소유권

| 영역 | 사용자 과업 | 조합·규격 | 데이터·행동 소유자 |
| --- | --- | --- | --- |
| App 진입 | 실행부 연결 후 현재 작업 열기 | UpdateAccess·DriverSessionAccess·LicenseAccess → RuntimeConnection → StudioScreen | App이 포트와 진입 단계 조합 |
| 앱 헤더 | 제품 확인, 테마 변경, 앱 명령 | ProductHeading, ThemePicker | StudioScreen 배치; Core 표시·선택 동작 |
| 그래프 사이드바 | 현재 편집 그래프 선택·새 그래프 생성 | 그래프 목록, SidebarToggle, GraphCreateDialog | GraphList·useGraphCatalog |
| 작업 헤더 | 이름·파일 동작·현재 그래프 확인 | WorkspaceHeader, TitleField, 메뉴 | RoutingWorkspace·WorkspaceFileMenu |
| 그래프 | 소스 → 처리 → 출력 연결, Options 편집 | AudioGraphCanvas, AudioNodeCard, Core 입력·미터 | RoutingWorkspace가 실행부 문서·명령·계측 연결 |
| 복구 영역 | 초안·저장·배치·파라미터 문제 복구 | InlineNotice, RetryAlert, RecoveryActions | 실패 종류별 Feature 소유자 |
| 하단 상태 | 버전·인증 확인, 전체 오디오 Pause/Resume | ApplicationStatusBar, 상태 진입점, transport | LicenseAccess·AudioPauseControl |
| dialog | 생성·이름·삭제·인증·정보 작업 | Core Dialog + 필드 + FormActions | 해당 Feature가 요청과 결과 연결 |

의존 방향은 `React Aria / React Flow → Core → Feature → Screen`이다. Screen·Feature는 의미·문구·값·동작을 전달하고 Core 내부 선택자나 임의 스타일로 공통 규격을 덮어쓰지 않는다.

## 2. Workspace 정상 상태

앱 소스를 추가하고 게인·장치·레코더에 연결한다. 그래프 선택은 편집 대상이며 실제 실행 여부와 독립이다. 앱 노드는 발견된 실제 앱 아이콘을 사용하고, 없거나 로드에 실패할 때만 공통 fallback을 표시한다.

<Canvas of={Workspace.Light} story={{ inline: false, height: 800 }} />

같은 화면의 <a href="/?path=/story/app-workspace--dark" target="_top">Dark</a>, <a href="/?path=/story/app-workspace--all-effects" target="_top">All Effects</a>, <a href="/?path=/story/app-workspace--long-graph-list" target="_top">Long Graph List</a>를 비교한다. All Effects는 실제 내장 효과 노드와 조작을 포함하며, DSP·음질 검증은 수행하지 않는다.

### 읽기 순서·스크롤·포커스

| 위치 | 계약 |
| --- | --- |
| 화면 shell | 창 높이에 고정. 페이지 전체를 스크롤시키지 않음 |
| 그래프 목록 | 목록 안에서 세로 스크롤. 끝에서 바깥 앱으로 스크롤 전달하지 않음 |
| 설정·메뉴 | 해당 콘텐츠 안에서 스크롤. 펼쳐도 노드·현재 값의 맥락 유지 |
| 사이드바 | 720px 이하에서는 작업 영역 위에 목록을 배치. Hide/Show는 같은 SidebarToggle |
| 그래프 선택 | 목록 버튼의 현재 그래프 표시와 노드/선택 포커스를 구별 |
| 노드 조작 | 바깥 노드가 선택을 소유. 내부 버튼·입력은 각각 실제 동작만 소유 |
| dialog 종료 | 트리거 또는 인접한 남은 조작으로 복귀. 바깥 화면에서 Tab을 가두지 않음 |
| 입력·Options | 그래프 삭제·이동 키와 분리. 장치 이름 → 채널 → 샘플레이트 → 비트 심도 → 출력 버퍼 순서 |

하단 인증 상태 버튼과 오디오 버튼은 각각 하나의 포커스 대상이다. 읽기 전용 미터·상태·앱 아이콘에는 별도 Tab 정지점을 만들지 않는다.

## 3. 빈 상태

빈 그래프는 실행부 조회에 성공한 `nodes=[] / edges=[]` 문서다. 연결 중이나 unavailable을 빈 그래프로 표시하지 않는다. 그래프 identity와 파일/이름/추가 진입점은 유지한다.

<Canvas of={Workspace.Empty} story={{ inline: false, height: 720 }} />

이 표본은 fixture 문서에서 노드와 연결만 비운다. 실제 Driver 장치 삭제·저장 초기화를 수행하지 않는다. 무료·유료 한도는 추가하려는 행동에 적용한다.

다음 표본은 일반 revision 갱신과 별개인 명령 응답 실패다. play는 실제 Add node → Output → Recorder를 실행하고 첫 제출 응답만 503으로 실패시킨다. 불확실한 명령을 자동 반복하지 않고 레코더 초안·실패 이유·“다시 시도” 하나를 유지한다. 재시도는 최신 실행부 문서에 자동 병합한 뒤 초안을 적용한다. 덮어쓰기/편집 취소를 요구하지 않는다. fixture에서는 레코더가 아직 실행부에 적용되지 않았으며 실제 녹음은 시작하지 않는다.

<Canvas of={Routing.SubmissionRecovery} story={{ inline: false, height: 720, autoplay: true }} />

연결 후 단절은 초기 연결 실패와 구별한다. RuntimeConnection은 이미 열었던 작업 화면을 숨김·inert 상태로 보존하여 재연결 후 같은 상태를 사용한다. 이 문서의 초기 연결 fixture는 단절 이후 초안 보존을 재현하지 않으며 해당 수명·응답 경합은 회귀 검사 범위다.

<a href="/?path=/story/features-devices-driverstatuscard--ready" target="_top">DriverStatusCard</a>는 ready·설치 중·재시작 필요·권한 거부·호환 불일치·unavailable 등의 진단 상태를 보여주는 독립 Feature 표본이다. 현재 App Workspace가 이 카드를 소비하지는 않는다. 실제 App의 Driver 상태는 DriverSessionAccess가 읽고, 미설치 안내는 DriverInstallNotice가 표시한다. 카드의 상태 표본을 앱에 이미 존재하는 설정 페이지로 설명하지 않는다.

## 5. 편집 제한·읽기 전용·외부 변경

| 구분 | 의미 | 적용 범위 |
| --- | --- | --- |
| 입력 readOnly | 필드 값을 읽되 편집 불가 | Core TextField의 실제 prop. <a href="/?path=/story/core-design-system-component-catalog--overview" target="_top">Catalog / Feedback</a> |
| interactionDisabled | 상위 카탈로그·세션 작업 중 관련 편집 제한 | RoutingWorkspace의 공개 prop. 그래프·미터 표시는 유지하며 노드 제어값 조회는 idle일 때 수행 |
| pending / applying | 요청 소유자가 결과를 기다리는 단계 | 중복 명령·무효 변경 제한, 확인 전 성공으로 표시하지 않음 |
| blocked / 복구 | 초안 보존·실패 이유·종류에 맞는 복구 행동 | 통신 실패는 다시 시도 하나. 지속 충돌에만 편집본 적용/편집 취소 선택. 단순 readOnly prop 아님 |
| 외부 설정·revision 변경 | 실행부의 최신 확인 값 자동 반영 | 실제 변경한 항목만 자동 병합. 반복 revision 거부도 제한 시간 안에서 다시 병합; 무효 Undo 초기화·삭제된 노드 복원 금지 |
| 외부 배치·revision 변경 | 최신 배치에 실제 변경한 좌표·크기·viewport 자동 병합 | 반복 확정 거부도 제한 시간 내 병합. 오디오 설정 revision과 분리; 무슨 배치를 불러올지 선택 요구하지 않음 |
| 배치 조회·저장 실패 | 로컬 배치 보존·“다시 시도” 하나 | 조회 실패는 내부에서 다시 읽고 저장 실패는 최신 배치에 자동 병합. 임의 Reload 선택으로 편집본을 버리지 않음 |

아래 표본은 처음부터 공개 `interactionDisabled=true`를 전달한다. 노드 제어값을 아직 확인하지 않아 Off/Mute 조작은 표시하지 않는다. 정상 상태에서 제어값을 확인한 뒤 제한되면 해당 버튼을 disabled로 유지하며, 이 전환은 `RoutingWorkspace.contract.test.tsx`에서 검사한다. 그래프 이름·Options·Add node를 포함한 전체 입력 차단은 상위 StudioScreen의 inert가 소유한다.

<Canvas of={Routing.EditingLocked} story={{ inline: false, height: 720 }} />

일반 업데이트마다 그래프 선택이나 덮어쓰기/편집 취소를 묻지 않는다. 아래 표본은 실제 레코더 추가 중 다른 작성자가 trim 노드를 두 번 추가해 revision을 진행시킨다. 레코더와 외부 변경 둘이 자동 병합되고 복구 선택 없이 정상 상태로 돌아가는 흐름이다.

<Canvas of={Routing.AutomaticRevisionMerge} story={{ inline: false, height: 720, autoplay: true }} />

<a href="/?path=/story/features-routing-workspace--external-settings" target="_top">External Settings</a>와 <a href="/?path=/story/features-routing-workspace--external-layout-revision" target="_top">External Layout Revision</a>은 외부 변경을 fixture로 유발한다. 같은 revision의 그래프 전환에서도 이전 화면의 늦은 응답이 새 그래프를 덮어쓰지 않아야 한다.

### 인스턴스별 표시 이름

노드 이름 더블클릭, 노드 포커스의 F2, 단일 노드 메뉴의 표시 이름 변경으로 같은 편집 창을 엽니다. 128자 이내 이름을 trim해 그래프 표시 메타데이터에 저장하며, 빈 이름은 실제 원래 이름을 표시합니다. Escape는 취소하고 제출·취소 모두 해당 노드로 포커스를 돌려보냅니다. Source·앱·장치의 실제 이름, capture selector와 오디오 그래프는 변경하지 않습니다. 같은 앱 인스턴스 둘은 별칭으로 구별할 수 있으며 창·탭별 캡처를 새로 만드는 기능은 아닙니다.

<Canvas of={Names.Rename} story={{ inline: false, height: 640, autoplay: true }} />

별칭이 없으면 원래 이름을 placeholder로 표시합니다. 추가 버튼은 +만 보이며 행동 이름·툴팁·메뉴 이름과 키보드 동작을 유지합니다.

## 6. 전체 오디오 일시정지

실행부가 확인한 `enginePower.enabled=false`를 하단 Resume 상태와 노드 표시가 소비한다. 그래프·장치·설정은 유지한다. 노드 Off·Mute, 효과 Bypass, 개별 녹음 Pause·Stop과 의미가 다르다.

<Canvas of={Workspace.AudioPaused} story={{ inline: false, height: 720 }} />

이 표본의 Resume는 preview 포트의 메모리 상태를 변경한다. 실제 오디오 중지·재개나 녹음 파일을 검증하지 않는다. 제품에서는 전체 Pause 시간은 녹음하지 않으며, 개별적으로 Pause·Stop·삭제한 녹음을 자동 시작하지 않는다.

## 7. 무료·인증·제품 정보

무료 앱은 기간 제한 없는 기능 제한 체험이다. 음질 저하·잡음·추가 지연을 넣지 않는다. 무료 전환 시 기존 그래프·장치·녹음과 현재 작업을 보존하며 초과 구성의 추가·새 실행에 한도를 적용한다.

| 무료 계약 | 한도 |

## 10. 업데이트·Driver 설치 진입

업데이트는 헤더 UpdateAccess가 소유하며 인증 창이나 장치 Options와 구별합니다. MixRelay 하나의 설치 버전과 게시 버전을 표시합니다. 시작·24시간 간격 확인과 수동 재조회는 같은 useUpdatesSession을 사용합니다. 장치 미설치·실행부 불일치의 설치 복구 안내도 같은 MixRelay 전체 설치 파일을 제공합니다. 앱·Driver별 선택은 없습니다. 설치·업데이트는 장치·그래프·설정·녹음·인증을 보존합니다.

| 응답·상태 | 표시와 다음 행동 |
| --- | --- |
| checking | 확인 중 status; 중복 조회·다운로드 열기 잠금 |
| available | 설치 버전·게시 버전과 해당 자산 열기 |
| current | 확인된 같은 버전. 실패·미게시를 최신으로 표시하지 않음 |
| published | 설치 버전 미확인 또는 미설치; 게시 자산과 별도로 표시 |
| not_published | 게시 파일 없음. 다운로드 행동 없음 |
| 조회 실패 | unavailable. 설치 값을 유지하고 실패한 최신 버전·다운로드 목록 제거; 재조회 가능 |
| 다운로드 열기 실패 | 실패 alert; 다시 확인·열기 가능. 자동 설치하지 않음 |
| port=null | 업데이트 기능 진입 없음. 미게시·최신과 다른 capability 부재 |
