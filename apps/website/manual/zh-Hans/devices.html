MIXRELAY / 手册

设备与虚拟端点

使用 MixRelay IO 与其他应用交换音频。设备格式与录音格式分别设置。

发布前草稿。目前尚不提供公开下载或购买。本手册介绍当前源代码构建版本的行为；在下文所列环境中，仍需验证安装后的实际行为。

本页内容

  • 选择音频方向
  • 通道、采样率与 PCM
  • 处理缓冲区与延迟

01

选择音频方向

MixRelay IO 是默认虚拟设备。如需接收其他应用向它播放的音频，请通过 添加节点 → 音源 → MixRelay Virtual I/O 添加该设备，此方向为 设备 → 音频图。如需将音频图中的混音发送至 OBS 等应用，请通过 添加节点 → 输出 → MixRelay Virtual I/O 添加该设备，此方向为 音频图 → 设备。在 OBS 或 DAW 中，将 MixRelay IO 选为音频输入。

请连接所需通道。MixRelay 不会替您选择系统默认设备，也不会自动添加硬件监听路由。如需监听，请添加物理输出并连接混音。Driver 还提供从操作系统播放到采集的基本回环，不受编辑器音频图映射数量的限制。

删除音频图中的设备引用不会删除虚拟设备本身。有许可时，可通过 新建虚拟设备 创建设备。从状态菜单移除设备时，也会移除其已保存的设备设置；正在使用该设备的其他应用将失去对它的访问。

02

通道、采样率与 PCM

打开虚拟节点的 选项，可更改 设备名称、通道、采样率和 位深度。仅提供受支持的通用设置。重命名需要许可。状态菜单中的通道数选项为 2、4、8、16、32 和 64；底层设备在每个方向上支持 1–64 个通道。

macOS 支持的采样率为 44.1、48、88.2、96、176.4 和 192 kHz。设备格式为 Float32、PCM16、紧凑型 PCM24 和 PCM32。Linux 提供 PipeWire 支持的组合。物理设备则取决于各自的能力。内部 DSP 使用 Float32；更改设备位深度不会更改 WAV 录音格式。

更改格式会短暂中断音频。如果更改失败，请先检查消息和当前值，再重试。保存失败可能表示设备已更改，但新设置未能保存。

03

处理缓冲区与延迟

支持运行中更改时，页脚的 处理缓冲区 可更改引擎的 I/O 缓冲区。选中数值即会应用。出现可恢复的错误时，可使用 应用 重试受支持的设置。较小的缓冲区可减少缓冲延迟，但也可能更容易出现音频中断。如有断音，请增大缓冲区。

没有为每个虚拟设备单独设置的缓冲区选择器。其他应用会选择各自的客户端缓冲区。缓冲区延迟 是一个处理缓冲区的时长，并非输入/输出总延迟，也不保证 PipeWire 全局的 quantum 大小。使用多个物理设备时，可能需要采样率转换和时钟同步。

应用音频采集目前要求 48 kHz。页脚目前提供缓冲区控制，不提供处理采样率选择器。虚拟设备的采样率需在设备设置中编辑。部分原生插件尚无法转移预设状态，因此会阻止运行中更改格式。
