MIXRELAY / 手册

故障排查与诊断

更改或删除已保存的工作前，请先检查当前消息和信号路径。

发布前草稿。目前尚不提供公开下载或购买。本手册介绍当前源代码构建版本的行为；在下文所列环境中，仍需验证安装后的实际行为。

本页内容

  • 无声、声音重叠或断音
  • 更改未应用或未保存
  • 保存诊断报告

01

无声、声音重叠或断音

  1. 检查全局 暂停、节点电源、静音和已连接的通道编号。选中的音频图不代表其开启或关闭状态。
  2. 确认音源正在产生音频。按需检查采集或麦克风权限及重新选择应用。
  3. 检查物理输出及其硬件音量。对于 OBS 或 DAW，请在该应用中将 MixRelay IO 选为输入，并在 MixRelay 中连接 音频图 → 设备。
  4. 声音重叠时，请检查直接播放和监听路由。出现断音时，如果适配器支持更改，可尝试增大 处理缓冲区。

设备不可用时，请重新连接，并按需重新选择。如果已保存的格式被拒绝，或设备回滚失败，请按照消息提示重新应用受支持的格式。引擎连接和音频处理是不同状态：即使引擎可访问，音频仍可能显示为停止或失败。

如果 MixRelay 因引擎反复故障而暂停，请先检查最近的更改，再选择 继续。不支持基于 Docker 的音频；请使用正常的 Linux 用户会话，并安装所需版本的 PipeWire 和 WirePlumber。

02

更改未应用或未保存

未应用 并不表示音频正在运行。如果应用提示已保留编辑内容，请检查当前引擎状态，准备好后使用 重试。请勿快速重复执行结果不确定的命令。如果持续冲突时提供 用这些编辑内容覆盖引擎中的音频图 或 放弃编辑并重新加载引擎中的音频图，请选择应用当前草稿还是将其放弃。

音频运行时也可能出现保存警告。如有可能，请在关闭前保存一份工作区副本。如只需恢复布局，保存当前布局 可重试保存当前布局；加载已保存的布局 会用已保存的布局替换当前布局。效果器错误请参阅插件恢复指南。许可错误请检查连接和设备时钟；激活结果不确定时需要联系支持。

03

保存诊断报告

  1. 打开 MixRelay 后台状态菜单。
  2. 选择 保存诊断报告…。
  3. 选择 dump.json 的保存位置。请先检查内容，如支持人员要求，再附在支持邮件中。保存不会上传文件。

报告在规定上限内包含版本、操作系统、架构、设备格式、运行时状态和数值计数器信息，不包含音频、内存转储、原始日志、认证信息、用户路径、设备名称与 ID、音频图或应用列表。报告最多为 256 KiB，包含最多 64 份设备摘要。无法获取的观测值会标为不可用。导出不会启动已停止的音频。

一次只能进行一项导出。取消不会创建文件。替换现有文件需要操作系统的覆盖确认。如果保存失败，请检查目标位置后重试。其他需要提供的信息请参阅联系支持。
