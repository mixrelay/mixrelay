MIXRELAY / MANUAL

Troubleshooting and diagnostics

Check the current message and signal path before changing or removing saved work.

Prerelease draft. Public downloads and purchases are not available yet. These instructions describe the current source build; installed behaviour still needs verification in the environments noted below.

On this page

  • No sound, doubled audio or dropouts
  • Changes not applied or saved
  • Save a diagnostic report

01

No sound, doubled audio or dropouts

  1. Check global Pause, node power, Mute and the connected channel numbers. A selected graph is not an on/off indicator.
  2. Confirm that the source is producing audio. Check capture or microphone permissions and application reselection if needed.
  3. Check the physical output and its hardware volume. For OBS or a DAW, choose MixRelay IO as that app’s input and connect Graph → device in MixRelay.
  4. For doubled sound, check direct playback and monitoring routes. For dropouts, try a larger Processing buffer if the adapter supports changing it.

If a device is unavailable, reconnect it and reselect it where necessary. If a saved format was rejected or device rollback failed, reapply a supported format as the message directs. Engine connection and audio processing are separate: a reachable engine can still report stopped or failed audio.

If MixRelay pauses after repeated engine failures, review recent changes before choosing Resume. Docker-backed audio is unsupported; use a normal Linux user session with the required PipeWire and WirePlumber versions.

02

Changes not applied or saved

Not applied is not confirmation of active audio. If the app reports that edits were preserved, review the current engine state and use Retry when ready. Do not repeat an uncertain command rapidly. If persistent conflicts offer Overwrite engine with these edits or Discard edits and reload engine, choose whether to apply your draft or discard it.

A save warning can appear while audio is active. Save a workspace copy if possible before closing. For layout-only recovery, Save current layout retries the current layout; Load saved layout replaces it with the saved layout. For effect errors, use the plug-in recovery guidance. For licence errors, check connectivity and the device clock; an uncertain activation requires support.

03

Save a diagnostic report

  1. Open the MixRelay background status menu.
  2. Choose Save Diagnostic Report….
  3. Select where to save dump.json. Review it and attach it to a support email if requested. Saving does not upload it.

The report contains bounded version, OS, architecture, device-format, runtime-state and numeric-counter information. It excludes audio, memory dumps, raw logs, authentication, user paths, device names and IDs, graphs and app lists. It is at most 256 KiB with up to 64 device summaries. Unavailable observations are marked unavailable. Export does not start stopped audio.

Only one export runs at a time. Cancelling creates no file. Replacing an existing file requires the OS overwrite confirmation. If saving fails, check the destination and retry. See support contact for what else to include.
