MIXRELAY / MANUEL

Périphériques et points de terminaison virtuels

Échangez de l’audio avec d’autres applications via MixRelay IO. Le format du périphérique est indépendant du format d’enregistrement.

Version provisoire avant publication. Les téléchargements et les achats ne sont pas encore ouverts au public. Ces instructions décrivent la version actuelle compilée à partir du code source. Le comportement après installation reste à vérifier dans les environnements indiqués ci-dessous.

01

Choisir le sens de l’audio

MixRelay IO est le périphérique virtuel par défaut. Pour recevoir l’audio qu’une autre application lui envoie, ajoutez-le via Ajouter un nœud → Source → MixRelay Virtual I/O. Il s’agit du sens Périphérique → graphe. Pour envoyer le mixage d’un graphe à une application comme OBS, ajoutez le périphérique via Ajouter un nœud → Sortie → MixRelay Virtual I/O. Il s’agit du sens Graphe → périphérique. Dans OBS ou votre DAW, sélectionnez MixRelay IO comme entrée audio.

Connectez les canaux nécessaires. MixRelay ne sélectionne pas le périphérique par défaut du système et ne crée pas de trajet d’écoute vers le matériel à votre place. Pour l’écoute, ajoutez une sortie physique et connectez-y le mixage. Le Driver fournit aussi un bouclage de base de la lecture du système vers la capture, indépendant des limites d’affectation du graphe dans l’éditeur.

Supprimer une référence dans le graphe ne supprime pas le périphérique virtuel. Avec une licence, la création de périphériques est accessible via Nouveau périphérique virtuel. Supprimer un périphérique depuis le menu d’état supprime aussi ses paramètres enregistrés ; les autres applications qui l’utilisent perdent ce périphérique.

02

Canaux, fréquences d’échantillonnage et PCM

Ouvrez les Options du nœud virtuel pour modifier Nom du périphérique, Canaux, Fréquence d’échantillonnage et Profondeur de bits. Seuls les réglages pris en charge dans les deux directions sont proposés. Le renommage nécessite une licence. Le menu d’état propose 2, 4, 8, 16, 32 et 64 canaux ; le périphérique sous-jacent prend en charge 1–64 canaux par direction.

Sur macOS, les fréquences prises en charge sont 44.1, 48, 88.2, 96, 176.4 et 192 kHz. Les formats de périphérique sont Float32, PCM16, PCM24 compacté et PCM32. Linux propose les combinaisons prises en charge par PipeWire. Les périphériques physiques suivent leurs propres capacités. Le DSP interne utilise Float32 ; modifier la profondeur de bits du périphérique ne change pas le format d’enregistrement WAV.

Un changement de format interrompt brièvement l’audio. En cas d’échec, vérifiez le message et la valeur actuelle avant de réessayer. Un échec d’enregistrement des paramètres peut signifier que le périphérique a été modifié, mais que ses nouveaux réglages n’ont pas été sauvegardés.

03

Tampons de traitement et latence

Le Tampon de traitement du pied de fenêtre modifie le tampon d’E/S du moteur lorsque les changements en cours d’exécution sont pris en charge. Sélectionner une valeur l’applique. En cas d’erreur récupérable, Appliquer permet de réessayer un réglage pris en charge. Un tampon plus petit peut réduire son délai, mais augmenter le risque de coupures. Augmentez-le si l’audio s’interrompt.

Il n’y a pas de sélecteur de tampon distinct pour chaque périphérique virtuel. Les autres applications choisissent leurs propres tampons clients. Délai du tampon indique la durée d’un tampon de traitement, pas la latence totale d’entrée/sortie. Cette valeur ne garantit pas un quantum commun à tout PipeWire. Plusieurs périphériques physiques peuvent nécessiter une conversion de fréquence d’échantillonnage et une synchronisation des horloges.

La capture d’applications nécessite actuellement 48 kHz. Le pied de fenêtre propose un réglage du tampon, pas un sélecteur de fréquence d’échantillonnage du traitement. La fréquence des périphériques virtuels se modifie dans leurs paramètres. Certains plug-ins natifs empêchent les changements de format en cours d’exécution, car l’état de leurs préréglages ne peut pas encore être transféré.
