MIXRELAY / 手冊

裝置與虛擬端點

使用 MixRelay IO 與其他應用程式交換音訊。裝置格式與錄音格式分開設定。

發佈前草稿。目前尚未提供公開下載或購買。本手冊說明目前原始碼建置版本的行為；在下文所列環境中，仍須驗證安裝後的實際行為。

本頁內容

  • 選擇音訊方向
  • 聲道、取樣率與 PCM
  • 處理緩衝區與延遲

01

選擇音訊方向

MixRelay IO 是預設虛擬裝置。如需接收其他應用程式向它播放的音訊，請透過 新增節點 → 音源 → MixRelay Virtual I/O 加入該裝置，此方向為 裝置 → 音訊圖。如需將音訊圖中的混音傳送至 OBS 等應用程式，請透過 新增節點 → 輸出 → MixRelay Virtual I/O 加入該裝置，此方向為 音訊圖 → 裝置。在 OBS 或 DAW 中，將 MixRelay IO 選為音訊輸入。

請連接所需聲道。MixRelay 不會替您選擇系統預設裝置，也不會自動加入硬體監聽路由。如需監聽，請加入實體輸出並連接混音。Driver 也提供從作業系統播放到擷取的基本迴送，不受編輯器音訊圖對應數量的限制。

刪除音訊圖中的裝置參照不會刪除虛擬裝置本身。有授權時，可透過 新增虛擬裝置 建立裝置。從狀態選單移除裝置時，也會移除其已儲存的裝置設定；正在使用該裝置的其他應用程式將無法繼續存取它。

02

聲道、取樣率與 PCM

開啟虛擬節點的 選項，可變更 裝置名稱、聲道、取樣率和 位元深度。僅提供支援的通用設定。重新命名需要授權。狀態選單中的聲道數選項為 2、4、8、16、32 和 64；底層裝置在每個方向上支援 1–64 個聲道。

macOS 支援的取樣率為 44.1、48、88.2、96、176.4 和 192 kHz。裝置格式為 Float32、PCM16、緊密封裝的 PCM24 和 PCM32。Linux 提供 PipeWire 支援的組合。實體裝置則依各自的能力而定。內部 DSP 使用 Float32；變更裝置位元深度不會變更 WAV 錄音格式。

變更格式會短暫中斷音訊。如果變更失敗，請先檢查訊息和目前值，再重試。儲存失敗可能表示裝置已變更，但新設定未能儲存。

03

處理緩衝區與延遲

支援運作中變更時，頁尾的 處理緩衝區 可變更引擎的 I/O 緩衝區。選取數值即會套用。出現可復原的錯誤時，可使用 套用 重試支援的設定。較小的緩衝區可減少緩衝延遲，但也可能更容易出現音訊中斷。如有斷音，請增大緩衝區。

沒有為每個虛擬裝置獨立設定的緩衝區選擇器。其他應用程式會選擇各自的用戶端緩衝區。緩衝區延遲 是一個處理緩衝區的時間長度，並非輸入/輸出總延遲，也不保證 PipeWire 全域的 quantum 大小。使用多個實體裝置時，可能需要取樣率轉換和時鐘同步。

應用程式音訊擷取目前需要 48 kHz。頁尾目前提供緩衝區控制，不提供處理取樣率選擇器。虛擬裝置的取樣率須在裝置設定中編輯。部分原生外掛程式尚無法轉移預設狀態，因此會阻止運作中變更格式。
