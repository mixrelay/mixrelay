MIXRELAY / MANUAL

장치와 가상 장치

MixRelay IO로 다른 앱과 오디오를 주고받으세요. 장치 형식과 녹음 파일 형식은 별개입니다.

사전 공개 초안입니다. 공개 다운로드와 구매는 아직 제공하지 않습니다. 현재 소스 빌드를 기준으로 작성했으며 아래에 표시한 환경의 설치본 검증은 남아 있습니다.

01

오디오 방향 선택

기본 가상 장치는 MixRelay IO입니다. 다른 앱이 이 장치로 재생한 소리를 받으려면 노드 추가 → 소스 → 가상 장치에서 선택하세요. 장치 → 그래프 방향입니다. OBS 같은 앱으로 그래프 믹스를 보내려면 노드 추가 → 출력 → 가상 장치에서 선택하세요. 그래프 → 장치 방향입니다. OBS나 DAW의 오디오 입력으로 MixRelay IO를 선택하세요.

필요한 채널을 연결하세요. MixRelay는 시스템 기본 장치를 바꾸거나 하드웨어 모니터링 경로를 자동으로 추가하지 않습니다. 들으려면 물리 출력을 추가하고 믹스를 연결하세요. Driver는 편집 그래프 매핑 한도와 별개로 OS 재생에서 캡처로 전달하는 기본 루프백도 제공합니다.

그래프의 참조를 지워도 가상 장치는 남습니다. 유료 인증이 있으면 새 가상 장치로 장치를 만들 수 있습니다. 상태 메뉴에서 장치를 제거하면 저장된 장치 설정도 지워지며 다른 앱에서도 해당 장치를 사용할 수 없게 됩니다.

02

채널·샘플레이트·PCM

가상 노드의 옵션에서 장치 이름·채널 수·샘플레이트·비트 심도를 바꾸세요. 양방향에서 함께 지원하는 설정만 제공합니다. 이름 변경은 유료 기능입니다. 상태 메뉴의 채널 선택은 2·4·8·16·32·64이며 장치 자체는 방향별 1–64채널을 지원합니다.

macOS 샘플레이트는 44.1·48·88.2·96·176.4·192 kHz입니다. 장치 형식은 Float32·PCM16·packed PCM24·PCM32입니다. Linux는 PipeWire가 지원하는 조합을 제공합니다. 물리 장치는 해당 하드웨어의 지원 범위를 따릅니다. 내부 DSP는 Float32를 사용하며 장치 비트 심도를 바꿔도 WAV 녹음 형식은 바뀌지 않습니다.

형식 변경 중 오디오가 잠시 끊깁니다. 실패하면 메시지와 현재 값을 확인한 뒤 다시 시도하세요. 저장 실패는 장치를 변경했지만 새 설정을 저장하지 못했다는 뜻일 수 있습니다.

03

처리 버퍼와 지연

하단의 처리 버퍼는 실행 중 변경을 지원할 때 엔진의 I/O 버퍼를 바꿉니다. 값을 선택하면 적용됩니다. 복구 가능한 오류가 있으면 적용으로 지원하는 설정을 다시 시도하세요. 버퍼를 줄이면 버퍼 지연이 줄어들 수 있지만 소리가 끊길 가능성은 높아질 수 있습니다. 소리가 끊기면 버퍼를 늘려 보세요.

가상 장치별 버퍼 선택기는 없습니다. 다른 앱은 자체 클라이언트 버퍼를 선택합니다. 버퍼 지연은 처리 버퍼 한 개의 시간이며 전체 입출력 지연이 아닙니다. PipeWire 전체의 quantum을 보장하는 값도 아닙니다. 여러 물리 장치를 함께 사용하면 샘플레이트 변환과 클록 동기화가 필요할 수 있습니다.

현재 앱 캡처는 48 kHz에서 지원됩니다. 하단에는 버퍼 조작이 있으며 처리 샘플레이트 선택기는 없습니다. 가상 장치의 샘플레이트는 장치 설정에서 바꿉니다. 일부 네이티브 플러그인은 프리셋 상태 이전이 구현되지 않아 실행 중 형식 변경을 막습니다.
