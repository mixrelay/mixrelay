저장된 작업을 바꾸거나 지우기 전에 현재 메시지와 신호 경로를 확인하세요.

사전 공개 초안입니다. 공개 다운로드와 구매는 아직 제공하지 않습니다. 현재 소스 빌드를 기준으로 작성했으며 아래에 표시한 환경의 설치본 검증은 남아 있습니다.

이 페이지 목차

  • 소리 없음·겹침·끊김
  • 적용·저장 실패
  • 진단 리포트 저장

01

소리 없음·겹침·끊김

  1. 전체 일시정지·노드 전원·음소거·연결한 채널 번호를 확인하세요. 그래프 선택은 켜짐·꺼짐 표시가 아닙니다.
  2. 소스에서 소리가 나오는지 확인하세요. 필요하면 캡처·마이크 권한과 앱 다시 선택을 확인하세요.
  3. 물리 출력과 하드웨어 볼륨을 확인하세요. OBS나 DAW에서는 MixRelay IO를 입력으로 선택하고 MixRelay의 그래프 → 장치를 연결하세요.
  4. 소리가 겹치면 직접 재생과 모니터링 경로를 확인하세요. 끊기면 어댑터가 변경을 지원할 때 처리 버퍼를 늘려 보세요.

장치를 쓸 수 없으면 다시 연결하고 필요에 따라 다시 선택하세요. 저장된 형식이 거부되거나 이전 설정 복구에 실패하면 메시지에 따라 지원하는 형식을 다시 적용하세요. 엔진 연결과 오디오 처리는 별개입니다. 엔진에 연결돼 있어도 오디오 중지·실패가 표시될 수 있습니다.

반복된 엔진 실패로 일시정지했다면 최근 변경을 확인한 뒤 재개하세요. Docker 기반 오디오는 지원하지 않습니다. 필요한 PipeWire·WirePlumber 버전이 있는 일반 Linux 사용자 세션을 사용하세요.

02

적용·저장 실패

적용되지 않음은 오디오 실행이 확인됐다는 뜻이 아닙니다. 편집을 보존했다는 안내가 나오면 현재 엔진 상태를 확인하고 준비되면 다시 시도하세요. 결과가 불확실한 명령을 빠르게 반복하지 마세요. 지속적인 충돌로 편집본으로 엔진에 덮어쓰기 또는 편집 취소하고 엔진 상태 불러오기가 제공되면 편집본을 적용할지 버릴지 선택하세요.

오디오가 실행 중이어도 저장 경고가 나올 수 있습니다. 가능하면 종료 전에 작업 공간 사본을 저장하세요. 배치만 복구할 때 현재 배치 저장은 현재 배치를 다시 저장하고 저장된 배치 불러오기는 저장된 배치로 바꿉니다. 효과 오류는 플러그인 복구 안내를 따르세요. 인증 오류는 연결·기기 시간을 확인하고 활성화 결과가 불확실하면 지원팀에 문의하세요.

03

진단 리포트 저장

  1. MixRelay 백그라운드 상태 메뉴를 여세요.
  2. 진단 리포트 저장…을 선택하세요.
  3. dump.json을 저장할 위치를 정하세요. 내용을 확인하고 요청받으면 지원 메일에 첨부하세요. 저장만으로 업로드하지 않습니다.

리포트는 버전·OS·아키텍처·장치 형식·실행 상태·수치 카운터를 정해진 범위 안에서 담습니다. 오디오·메모리 덤프·원시 로그·인증·사용자 경로·장치 이름과 ID·그래프·앱 목록은 제외합니다. 최대 256 KiB이며 장치 요약은 최대 64개입니다. 확인할 수 없는 값은 확인 불가로 기록합니다. 내보내기 때문에 멈춘 오디오를 시작하지 않습니다.

한 번에 하나만 내보냅니다. 취소하면 파일을 만들지 않습니다. 기존 파일 교체는 OS 덮어쓰기 확인이 필요합니다. 저장에 실패하면 위치를 확인하고 다시 시도하세요. 함께 보낼 정보는 지원 문의에서 확인하세요.
