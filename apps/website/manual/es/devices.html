MIXRELAY / MANUAL

Dispositivos y conexiones virtuales

Usa MixRelay IO para intercambiar audio con otras aplicaciones. El formato del dispositivo es independiente del formato de grabación.

Borrador previo al lanzamiento. Las descargas y las compras públicas aún no están disponibles. Estas instrucciones describen la compilación actual del código fuente; aún queda por verificar el comportamiento de la instalación en los entornos indicados a continuación.

01

Elegir la dirección del audio

MixRelay IO es el dispositivo virtual predeterminado. Para recibir el audio que otra aplicación reproduce en él, añádelo desde Añadir nodo → Fuente → MixRelay Virtual I/O. Esta dirección es Dispositivo → grafo. Para enviar la mezcla de un grafo a una aplicación como OBS, añade el dispositivo desde Añadir nodo → Salida → MixRelay Virtual I/O. Esta dirección es Grafo → dispositivo. En OBS o en tu DAW, selecciona MixRelay IO como entrada de audio.

Conecta los canales que necesites. MixRelay no selecciona un dispositivo predeterminado del sistema ni añade una ruta de monitorización por hardware por ti. Para monitorizar, añade una salida física y conecta la mezcla a ella. Driver también ofrece un bucle de audio básico desde la reproducción del sistema operativo hasta la captura, sin los límites de mapeo del grafo del editor.

Eliminar una referencia del grafo no elimina el dispositivo virtual. Con una licencia, puedes crear dispositivos mediante Nuevo dispositivo virtual. Eliminar un dispositivo desde el menú de estado también elimina sus ajustes guardados; las demás aplicaciones que lo utilicen perderán ese dispositivo.

02

Canales, frecuencias de muestreo y PCM

Abre Opciones del nodo virtual para cambiar Nombre del dispositivo, Canales, la frecuencia de muestreo y Profundidad de bits. Solo se ofrecen ajustes comunes compatibles. Para cambiar el nombre se necesita una licencia. El menú de estado permite elegir 2, 4, 8, 16, 32 y 64 canales; el dispositivo subyacente admite 1–64 canales por dirección.

En macOS, las frecuencias compatibles son 44.1, 48, 88.2, 96, 176.4 y 192 kHz. Los formatos de dispositivo son Float32, PCM16, PCM24 empaquetado y PCM32. Linux ofrece las combinaciones compatibles con PipeWire. Los dispositivos físicos dependen de sus propias capacidades. El DSP interno usa Float32; cambiar la profundidad de bits del dispositivo no cambia el formato de grabación WAV.

Un cambio de formato interrumpe brevemente el audio. Si falla, revisa el mensaje y el valor actual antes de volver a intentarlo. Un error al guardar puede significar que el dispositivo ha cambiado, pero sus nuevos ajustes no se han guardado.

03

Búferes de procesamiento y latencia

El control Búfer de procesamiento de la barra inferior cambia el búfer de E/S del motor cuando se admiten cambios durante el funcionamiento. Al seleccionar un valor, se aplica. Si hay un error recuperable, Aplicar vuelve a intentar aplicar un ajuste compatible. Un búfer menor puede reducir el retardo del búfer, pero aumenta el riesgo de cortes. Auméntalo si el audio se entrecorta.

No hay un selector de búfer independiente para cada dispositivo virtual. Las demás aplicaciones eligen sus propios búferes de cliente. Retardo del búfer es la duración de un búfer de procesamiento, no la latencia total de entrada y salida. No garantiza un tamaño de bloque común para todo PipeWire. Usar varios dispositivos físicos puede requerir conversión de frecuencia de muestreo y sincronización de relojes.

La captura de aplicaciones requiere actualmente 48 kHz. La barra inferior ofrece un control de búfer, pero no un selector de frecuencia de muestreo de procesamiento. Las frecuencias de los dispositivos virtuales se modifican en sus ajustes. Algunos plug-ins nativos impiden los cambios de formato durante el funcionamiento porque aún no se puede transferir el estado de sus preajustes.
