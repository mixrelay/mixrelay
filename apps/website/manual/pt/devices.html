MIXRELAY / MANUAL

Dispositivos e conexões virtuais

Use o MixRelay IO para trocar áudio com outros aplicativos. O formato do dispositivo é independente do formato de gravação.

Rascunho de pré-lançamento. Os downloads e as compras públicas ainda não estão disponíveis. Estas instruções descrevem a compilação atual do código-fonte; o comportamento após a instalação ainda precisa ser verificado nos ambientes indicados abaixo.

01

Escolher a direção do áudio

MixRelay IO é o dispositivo virtual padrão. Para receber o áudio que outro aplicativo reproduz nele, adicione-o por Adicionar nó → Fonte → MixRelay Virtual I/O. Essa direção é Dispositivo → grafo. Para enviar a mixagem de um grafo a um aplicativo como o OBS, adicione o dispositivo por Adicionar nó → Saída → MixRelay Virtual I/O. Essa direção é Grafo → dispositivo. No OBS ou na sua DAW, selecione MixRelay IO como entrada de áudio.

Conecte os canais necessários. O MixRelay não seleciona um dispositivo padrão do sistema nem adiciona uma rota de monitoração por hardware para você. Para monitorar, adicione uma saída física e conecte a mixagem a ela. O Driver também oferece loopback básico da reprodução do sistema operacional para a captura, sem os limites de mapeamento do grafo do editor.

Remover uma referência no grafo não remove o dispositivo virtual. Com uma licença, é possível criar dispositivos por Novo dispositivo virtual. Remover um dispositivo pelo menu de status também remove suas configurações salvas; outros aplicativos que o utilizam perdem esse dispositivo.

02

Canais, taxas de amostragem e PCM

Abra Opções do nó virtual para alterar Nome do dispositivo, Canais, a taxa de amostragem e Profundidade de bits. Só são oferecidas configurações comuns compatíveis. Renomear exige uma licença. O menu de status oferece 2, 4, 8, 16, 32 e 64 canais; o dispositivo subjacente aceita 1–64 canais por direção.

No macOS, as taxas compatíveis são 44.1, 48, 88.2, 96, 176.4 e 192 kHz. Os formatos de dispositivo são Float32, PCM16, PCM24 empacotado e PCM32. O Linux oferece as combinações aceitas pelo PipeWire. Os dispositivos físicos seguem suas próprias capacidades. O DSP interno usa Float32; alterar a profundidade de bits do dispositivo não altera o formato da gravação WAV.

Uma mudança de formato interrompe brevemente o áudio. Se falhar, confira a mensagem e o valor atual antes de tentar novamente. Uma falha ao salvar pode significar que o dispositivo foi alterado, mas suas novas configurações não foram salvas.

03

Buffers de processamento e latência

O controle Buffer de processamento na barra inferior altera o buffer de E/S do mecanismo quando há suporte a mudanças durante o funcionamento. Selecionar um valor o aplica. Em caso de erro recuperável, Aplicar tenta aplicar novamente uma configuração compatível. Um buffer menor pode reduzir o atraso do buffer, mas aumentar a chance de cortes. Aumente-o se o áudio estiver entrecortado.

Não há um seletor de buffer separado para cada dispositivo virtual. Outros aplicativos escolhem seus próprios buffers de cliente. Atraso do buffer é a duração de um buffer de processamento, não a latência total de entrada e saída. Não garante um quantum comum a todo o PipeWire. Vários dispositivos físicos podem exigir conversão da taxa de amostragem e sincronização de relógios.

A captura de aplicativos exige atualmente 48 kHz. A barra inferior oferece controle de buffer, mas não um seletor de taxa de amostragem de processamento. As taxas dos dispositivos virtuais são alteradas nas configurações do dispositivo. Alguns plug-ins nativos impedem mudanças de formato durante o funcionamento porque ainda não é possível transferir o estado de suas predefinições.
