# MixRelay 워드마크 설계 근거

2026-10-12. 상태: 사용자 승인으로 Plex Optical 워드마크 동결.
[공식 에셋·사용 규격](../identity/wordmark/README.md)이 현재 배포 기준이다.
아래는 선정 과정과 정적 표본 검증 기록이다. 제품 화면 적용 완료를 뜻하지 않는다.
2026-10-11의 초기 세 안과 DIN 추천은 철회 상태를 유지한다.

## Plex 워드마크 초안 · 2026-10-12

사용자가 선택한 Plex 제품 서체와 Optical Grid 심벌에서 출발했다.
편집 마스터는 [mixrelay-plex-wordmark.ai](plex/mixrelay-plex-wordmark.ai) 하나다.
사용자 선택 후 Optical만 남겼다. 세 대지는 컬러·단색·반전, 글자·조합 규격,
축소·사용 예시다. A/C와 이전 정렬·간격 비교 그래픽은 현행 AI와 검토 이미지에서 제거했다.
[현행 Optical](plex/optical.png)과 [축소 표본](plex/scale.png)을 확인한다.

| 조건 | 초안 판단 |
| --- | --- |
| 원본 | Core `IBMPlexSans-Medium.woff2`. UPM 1000, cap 698, x-height 520. HarfBuzz로 실제 OpenType 조판 후 윤곽 추출 |
| 이전 A · Original Plex | 대조군으로 검토 후 제거 |
| B · Optical | 선택된 단일 초안. 둥근 i 점 전체를 46단위 낮춰 상단 698에 맞춤. l 상단 740→698, 발 끝 259→245. M/x/R/e/a/y는 원형 유지 |
| 추가 자간 | OpenType kerning 뒤에 Mi −12, ix −8, xR −30, Re −12, el −10, la −10, ay −12단위. 일괄 tracking·수평 축소를 사용하지 않음 |
| 이전 C · Squared | 네모 점과 직각 l의 연결성이 떨어져 제거 |
| 조합 비례 | 사용자 피드백을 반영해 cap/심벌 실루엣 1.00으로 수정. M/R/l의 상단과 기준선을 심벌의 위·아래에 맞춤. 빈 간격 0.26H 적용. y 꼬리는 기준선 아래 0.287H로 원형 유지. 글자는 이전보다 균일하게 33.3% 확대 |
| 색 소유자 | Core `brandColors`의 primary/ink/inverse/paper/dark |
| 축소 검토 | 심벌 캔버스 16/24/32px에서 cap 12.67/19/25.33px로 다시 비교. 이전 0.75 비례에 근거한 최소 24px 제안은 철회. 최종 최소 크기는 실제 설치본에서 판단하며 y가 내려오는 공간까지 확보 |
| 적용 범위 | Optical 동결 및 SVG 에셋화 완료. Core·앱·웹·Storybook 적용은 디자인 시스템 작업에서 별도로 수행. 사용 맥락은 정적 표본이며 실제 앱 검증이 아님 |

오디오 경로·처리·녹음을 제어하는 제품의 성격에 맞춰 UI와 같은 글자의 뼈대를 유지했다.
이름의 M/R 경계와 흰 공간을 정돈하고, 전부 Mono로 바꾸거나 파형·절개·합자를 덧붙이지 않았다.
이는 설계 판단이며 의무 표준이나 사용자 연구 결과가 아니다.

근거: [IBM 공식 서체 안내](https://www.ibm.com/design/language/typography/typeface/),
[IBM Plex 원본](https://github.com/IBM/plex), Core `fonts/sources.json`와 원본 OFL.
원본 폰트는 수정·서브셋하지 않았다. 변경한 것은 로고의 벡터 글자이며 새로운 폰트 파일로 배포하지 않는다.
[source.json](plex/source.json)에 원본 SHA-256, 윤곽·위치·자간·제안 비례를 기록했다.

검토 · 관찰 · 영향 · 수정:

- xR · 중앙 흰 공간이 넓음 · 이름이 둘로 갈라져 보임 · 기본 kerning 뒤 −30단위 보정.
- i/l · 대문자보다 높은 윗선 · 이름의 상단 리듬이 흔들림 · B에서 cap에 맞추고 둥근 점과 l의 발 유지.
- 심벌과 글자의 바닥 · y까지 포함한 외곽 중심 정렬로 글자 본체가 뜸 · 조합이 불안정해 보임 · M/R/l의 cap과 기준선을 심벌 실루엣에 맞추고 y만 아래로 내려오게 수정.
- 16px 캔버스 · 이전 cap 9.5px에 근거한 축소 판단 · 크기 수정 전후를 혼동할 수 있음 · cap 12.67px로 재검토하고 최종 최소 크기 판단은 보류.

검증 범위: Optical의 1× 16/24/32px 캔버스, 반전·단색, Illustrator 가져오기 화면,
AI 재열기 후 세 대지와 편집 가능한 벡터 글자의 보존. PNG 직접 내보내기는 실패해 같은 벡터 원본의
PDF 표본을 렌더링하고 Illustrator 미리보기와 대조했다. AI는 Illustrator 편집 데이터로 저장되며
다른 앱의 PDF 미리보기는 포함하지 않는다. 실제 설치본과 다른 OS의 렌더링은 미검증이다.

재생성: `plex/build.py`는 fontTools/brotli/uharfbuzz/reportlab을 사용한다. `plex/render.swift`는
표본 렌더러다. SVG/PDF 중간 파일은 `/tmp/mixrelay-plex-wordmark`에 생성하며 AI를 덮어쓰지 않는다.
가져오기용 임시 SVG는 작업 후 제거하며 납품 자산에 남기지 않는다.
이후 수작업 수정의 마스터는 AI이며 source.json과 검토 이미지를 해당 수정에 맞춰 갱신한다.

## 높이·기준선 수정 후 조합 리뷰 · 2026-10-12

대상은 Optical B의 cap/심벌 실루엣 1.00, 공통 기준선이다. 리뷰 당시 간격은 0.30H였으며,
사용자 승인 후 0.26H를 기존 AI의 현행 조합과 컬러·반전·축소·사용 예시에 적용했다.
같은 윤곽과 크기에서 간격만 0.22/0.26/0.30/0.34H로 비교했다.
당시 간격 비교는 primary·단색, cap 64px와 19px 표본으로 확인했다.
사용자의 정리 요청으로 비교 그래픽은 제거했고, 아래 관찰 기록만 보존한다.

| 위치 | 관찰 | 영향 | 권장 수정 |
| --- | --- | --- | --- |
| 심벌과 이름의 크기 | cap 1.00H에서 M/R/l의 위·아래가 맞고, 단색 심벌은 개별 글자보다 조밀하지만 전체 이름을 압도하지 않음 | 이전의 떠 있는 글자 본체는 해소. 동일한 높이가 동일한 시각 무게를 뜻하지는 않음 | 크기는 유지. 심벌을 더 키우거나 글자 굵기를 올릴 근거는 부족 |
| 심벌–M 간격 | 이전 0.30H는 큰 표본에서 약간 느슨함. 0.22H는 단색에서 두 수직 덩어리가 가까워지고, 0.34H는 분리가 더 강함. 0.26H가 둘을 묶으면서 분리도 유지 | 이전안은 실패 수준은 아니지만 크기·정렬의 정돈에 비해 결속이 덜함 | 0.26H 적용 완료. 0.30H 대비 약 13% 축소 |
| 작은 조합 | 올바른 비례의 16px 캔버스 표본은 이름을 읽을 수 있으나 심벌 내부와 i/e/a 디테일이 래스터 조건에 민감함 | 큰 이미지의 균형 판단만으로 최소 사용 크기를 확정하면 안 됨 | 실제 1× 설치본에서 확인 후 최소 크기 확정. 현재 리뷰는 정적 표본의 시각 판단 |

판정: 크기·기준선은 유지할 만하며 간격은 소폭 개선 여지가 있다.
추천 0.26H는 이 윤곽과 표본을 보고 내린 광학 판단이며 보편적인 로고 표준은 아니다.
리뷰 후 승인된 간격만 AI 마스터와 source.json, 검토 이미지에 반영했다.
원본 폰트, Core 토큰과 제품 자산은 수정하지 않았다.

## 이번 판단에서 잘못된 점

설치된 Helvetica Neue·DIN Alternate·Avenir Next에 굵기·자간·대소문자를 달리하고,
이를 곧바로 세 워드마크 방향으로 제시했다. 이름 표기, 조직의 제품 관계, 개별 글자의
조형, 심벌과의 조합을 검토하기 전에 추천을 붙였다. 예쁜 비교판과 path 변환은
그 설계 근거를 대신하지 못한다. DIN이 장비처럼 보인다는 설명만으로 선택하지 않는다.

`README.md`, `manifest.json`, 비교판의 상태를 철회로 바꿨다. 기존 배포 자산의
Helvetica Neue Regular도 최종 서체로 승인된 것으로 취급하지 않는다.

## 이름과 글자 구조

기본 검토 문자열은 `MixRelay`다. 두 단어의 경계와 M·R이 드러나며 현재 제품 이름과 이어진다.
`MIXRELAY`는 Sonolog와 같은 대문자 체계를 검토하는 비교 조건으로만 둔다.
`mixrelay`는 읽히는 이름의 구조와 조직의 표기 관계를 충분히 설명하기 전에는 선택하지 않는다.
대소문자를 바꿔 후보의 차이를 과장하지 않는다.

| 요소 | 확인할 조형 | 설계 판단 |
| --- | --- | --- |
| M | 세로 기둥, 전체 폭, 내부 V의 깊이 | 심벌의 M을 다시 작은 심벌로 복제하지 않는다. 문자의 M이 먼저 읽혀야 하며 과도하게 넓어 첫 글자만 강조되지 않아야 한다 |
| i·x | 점 크기·높이, x 교차의 검은 밀도 | 작은 크기에서도 점이 남고 x 중심이 덩어리가 되지 않아야 한다 |
| xR | x 사선과 R 수직줄 사이의 삼각형 빈 공간 | 동일한 수치 자간보다 실제 흰 공간을 비교한다. Mix와 Relay가 둘로 갈라지거나 서로 붙지 않아야 한다 |
| R | 위쪽 속공간과 아래 다리의 출발·끝 | 심벌과 공유할 부분은 단단한 기둥과 정리된 접합이다. 심벌의 기울기 0.5를 그대로 강제하면 문자 R의 비례가 망가질 수 있다 |
| e | 열린 입구·가로획·위아래 속공간 | 반전과 축소에서 입구가 닫히지 않아야 한다. 굵기만 올리면 안 된다 |
| l | 높이와 끝 처리, i와의 구별 | Relay의 l이 I처럼 보이거나 주변 글자 사이에 뜻밖의 큰 틈을 만들지 않아야 한다 |
| a | 2층 구조의 위쪽 입구와 아래 속공간 | 현재의 단단한 심벌과 함께 비교할 기준은 2층 a다. 1층 a는 실제 조합에서 더 나은 이유가 있을 때만 검토한다 |
| y | 두 사선의 결합과 내려오는 꼬리 | 끝 글자의 무게와 전체 기준선 아래 공간을 함께 정리한다. 꼬리를 잘라 가로 박스에 억지로 맞추지 않는다 |

심벌의 외곽 상단·내부·사선 접합 곡선은 각각 다른 광학 보정으로 구성됐다.
글자 전체에 같은 모서리 반경을 씌우거나 모든 획을 직선으로 만드는 방식으로
조직의 일관성을 설명하지 않는다. 최종 레터링에는 실제로 수정한 글자와 이유를 명시한다.

## 서체 제작사의 표본 검토

아래는 최종 후보 순위나 채택 목록이 아니다. 일반 폰트 이름을 붙이기 전에 실제 문자 구조와
대체 글리프를 확인하기 위한 참고다. 제작사의 공식 페이지와 시험 화면을 읽었다.

| 참고 | 제작사에서 확인한 구조·기능 | 이번 확인 범위와 남은 판단 |
| --- | --- | --- |
| [ABC Diatype](https://abcdinamo.com/typefaces/diatype) | 정폭과 비례폭 계열을 함께 제공하며 R·a·y의 대체 글리프가 있다. 화면 읽기를 염두에 둔 grotesque로 설명 | Medium 시험 화면에 실제 `MixRelay`를 넣고 M·R·e·a·y를 확인. 표준/대체 R·y와 심벌의 실제 조합 비교가 필요하며 최종 선택하지 않음 |
| [Söhne](https://klim.co.nz/fonts/soehne/) | 제작사는 Akzidenz-Grotesk와 Helvetica 계보, NYC Subway의 Standard Medium 표기를 출발점으로 설명 | Kräftig 시험 화면에 `MixRelay`를 넣어 확인. 굵기와 실측 높이를 맞춘 조합 검토 전이며 최종 선택하지 않음 |
| [Suisse Int’l](https://www.swisstypefaces.com/fonts/suisse/) | 제작사 자료는 비례폭·정폭·condensed를 포함한 공통 서체 체계를 설명 | 공식 계열 자료만 검토. 이번에 MixRelay 문자열을 시험하지 않았으므로 글자 적합성을 평가하지 않음 |

제작사의 설명은 서체의 계보·기능을 확인하는 근거다. MixRelay에 어울린다는 결론은
별도의 프로젝트 판단이다. 가격이 높거나 유명한 서체라는 이유로 추천하지 않는다.
시험용 웹 표본은 배포 로고 원본으로 사용하지 않았으며 글꼴 파일도 가져오지 않았다.

## 조합을 평가하는 조건

현재 배포 윤곽과 같은 Helvetica Neue Regular를 CoreText로 재측정한 결과는
`reference-current.json`에 보관했다. 대문자 높이 71.4에 대해 i의 몸통과 x 높이는
51.7이다. 현행 compact의 대문자 높이 10px에서 이 부분은 약 7.24px로 보인다.
따라서 큰 글자의 인상과 함께 작은 몸통·속공간이 남는지 확인해야 한다.
글자 잉크 bounds 사이 간격은 Mi 13.7, ix 6.5, xR 7.5, Re 5.3, la 9.2로 다르다.
이 값은 사선과 곡선의 실제 흰 공간을 반영한 광학 자간이 아니므로 숫자를 같게
만드는 근거로 사용하지 않는다.

글꼴 이름·pt 크기를 맞추는 것으로 비교를 끝내지 않는다. 동일한 문자열, 실측 대문자 높이,
선택한 심벌, 조직의 빨강과 잉크색, 동일한 배치 조건에서 검토한다.

- **검은 면의 균형:** M·R의 획과 심벌의 세 기둥을 함께 보고 전체 이름의 무게를 맞춘다.
  심벌의 획/틈 1:1 규칙을 문자에 그대로 강제하지 않는다.
- **소문자의 높이:** M·R만 비슷해도 `ix`·`elay`가 너무 작으면 이름이 두 덩어리로 보인다.
  대문자와 소문자 높이 비율을 함께 기록한다.
- **공간의 리듬:** Mi·ix·xR·Re·el·la·ay를 각각 확인한다. 균등 tracking을 넣고
  이를 광학 자간이라고 부르지 않는다.
- **심벌과의 높이:** 기존 H:H, 초기 시안 H:0.6H 모두 결정 근거가 부족했다.
  0.65H·0.75H·0.85H를 비교 조건으로 두고 실제 검은 면과 정렬로 판단한다.
  이 숫자는 새 제품 규격이 아니다.
- **조직 관계:** MixRelay와 실제 Sonolog 워드마크를 한 면에서 비교한다. 글꼴·대소문자가
  같아야 한다는 전제 없이 공통 색·글자 무게·간격·이름 위계를 평가한다.
- **실사용:** 제품 헤더의 심벌 16px/글자 10px, standard 24px, 웹 헤더, 문서 64px,
  흑백과 반전에서 실제 크기로 확인한다. 큰 확대판만으로 판정하지 않는다.

## 완료를 판단하는 결과물

다음 워드마크 검토에는 원형 서체와 수정 후 글자, 수정한 지점, 글자쌍별 간격,
동일 조건의 심벌 조합, Sonolog와 나란한 제품군 표기, 실제 작은 크기와 반전 결과가
함께 있어야 한다. 한 가지 기준을 공유하는 레터링의 변형을 비교하고,
근거가 다른 설치 폰트 세 개를 곧바로 후보로 제시하지 않는다.

이 기준으로 [레터링 A·B](lettering-v2/README.md)의 여덟 글자 윤곽을 직접 구성했다.
기존 형태와의 비교, 글자쌍 간격, 동일 심벌 조합, Sonolog 옆의 배치, 작은 크기와
반전을 시안으로 확인했다. 시안 제작 후 워드마크 전체를 보류하기로 결정했다. 제품은 확정 그래픽 심벌만 사용한다.
